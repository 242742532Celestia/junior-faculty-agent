# 写作雷区参考

本文件是 `assertive-writing` 技能的方法层说明，配合 `scripts/lint_redflags.py` 使用。

脚本只报 **A 段**（可机检、有形式特征）的问题；**B 段**（需人眼、依赖论证本身）只输出人工复核清单，不判定对错，也不计入问题计数。

---

## 1. A 段：可机检的雷区

### A1 空话套话堆砌

| 项 | 内容 |
|---|---|
| **为什么是雷区** | 空话占据篇幅却不携带任何信息。读者的注意力是有限资源，每一句套话都在稀释真正要读的那几句；成堆出现时，评审会直接判断作者没有实质内容。 |
| **典型示例（占位符）** | 改前：「在当今快速发展的时代，随着科技的不断进步，<方法 X> 成为了重要研究方向。」<br>改后：「<方法 X> 针对 <问题 Q>，需要 <数据条件 D> 才能训练。」 |
| **怎么改** | 删掉整句铺垫，把信息补进实质陈述。或直接删——多数情况下空话句删掉后段落更紧。 |
| **级别** | 同一句堆叠 2 处及以上 → high；单处 → medium。 |
| **识别信号** | 在当今……的时代 / 随着……的不断进步 / 日新月异 / 蓬勃发展 / 举世瞩目 / 具有重要意义 / 提供了有力支持 |

### A2 无信息量连接词滥用

| 项 | 内容 |
|---|---|
| **为什么是雷区** | 这类词是逻辑关系的**占位符**：它们宣告「下面有话要说」，但不说明是什么话。用多了等于把论证的骨架交给读者自己脑补。 |
| **典型示例（占位符）** | 改前：「值得注意的是，<结果 R>。综上所述，<结论 C>。」<br>改后：「<结果 R>。<结论 C>。」 |
| **怎么改** | 删除，或替换成**具体**的逻辑关系：「因此」「与之相反」「与 <方法 X> 相比」。实在需要保留时，删掉之后补上真正的理由。 |
| **级别** | 同一短语全文出现 ≥3 次 → high；2 次 → medium；1 次 → low。 |
| **识别信号** | 值得注意的是 / 不难看出 / 不难发现 / 综上所述 / 总而言之 / 总的来说 / 众所周知 / 显而易见 / 不言而喻 / 毫无疑问 / 毋庸置疑 |

### A3 中英混排标点错误

| 项 | 内容 |
|---|---|
| **为什么是雷区** | 标点不一致会让读者的解码速度下降，也让编辑与评审怀疑稿件的校对质量。更实际的问题是：半角句号在中文段落里可能被误读为小数点或缩写。 |
| **典型示例（占位符）** | 改前：「我们的结果表明,该方法有效, 结论稳定.」<br>改后：「我们的结果表明，该方法有效，结论稳定。」 |
| **怎么改** | 统一为中文全角标点：逗号「，」、句号「。」、分号「；」、冒号「：」、括号「（）」。英文术语与公式内部保留半角。括号不配对时逐个补齐或删除。 |
| **级别** | 括号不配对 → high；同一行 6 处以上半角标点 → high；3–5 处 → medium；同行全半角混用 → medium。 |
| **识别信号** | 中文语境中的半角 `,` `;` `:` `.`；`( )` 与 `（ ）` 数量不等；同行同时出现全角与半角逗号。 |

### A4 数字与单位不规范

| 项 | 内容 |
|---|---|
| **为什么是雷区** | 数字与单位是审稿人核对的第一批对象。写法不统一会被当成数据不可靠；缺空格在全角排版里尤其刺眼。 |
| **典型示例（占位符）** | 改前：「提升幅度为 5％，另一处写成 5%，样本量 10cm。」<br>改后：「提升幅度为 5%，样本量为 10 cm（或 10 厘米）。」 |
| **怎么改** | 全文统一百分号写法（推荐半角 `%`）；数字与西文单位之间加空格，或改用中文单位；小数点用半角「.」，不要用中文逗号「,」或全角「．」。 |
| **级别** | 全角小数点 / 中文逗号作小数点 → high；百分号混用、数字与单位未分隔 → medium；百分号前多余空格 → low。 |
| **识别信号** | `%` 与 `％` 同时出现；`10cm` 一类连写；`0，5` 一类中文逗号小数；`5 %` 一类百分号前空格。 |

### A5 引号 / 书名号 / 破折号不成对

| 项 | 内容 |
|---|---|
| **为什么是雷区** | 不成对的引号会让读者无法判断引用范围，严重的会造成**引文归属错误**——把作者自己的话误读成引文，或反之。这是评审会当作硬伤看的一类问题。 |
| **典型示例（占位符）** | 改前：「他提到“这一方法可以提升效果。」<br>改后：「他提到“这一方法可以提升效果”。」 |
| **怎么改** | 逐处补齐配对符号；中文破折号统一写成双破折号「——」；书名号《 》只用于文献、期刊、专著名称。 |
| **级别** | 引号 / 书名号不成对 → high；直引号数量为奇数 → high；单个破折号 → low。 |
| **识别信号** | `“”` `「」` `《》` 数量不等；直引号 `"` 数量为奇数；孤立的「—」。 |

### A6 段落长度异常

| 项 | 内容 |
|---|---|
| **为什么是雷区** | 超长段落把多个论点挤在一起，读者无法定位「这一句在论证什么」。中文长段的节奏感比英文更依赖分段，长段在中文期刊里的可读性损失更明显。 |
| **典型示例（占位符）** | 改前：<一个约 400 字、包含「背景 + 方法 + 结果 + 讨论」的段落><br>改后：拆成 4 段，每段一个论点，段首句直接给出该段论点。 |
| **怎么改** | 按论点切分：背景、设定、方法、主要结果、解释、边界各成段。**切分时保持每段是一个完整论点**，不要把一段话切成三半。 |
| **级别** | 超过阈值 2 倍 → high；超过阈值 → medium。阈值可用 `--max-para-chars` 调整，默认 300 字。 |
| **识别信号** | 连续非空行合并后字符数超过阈值。标题、表格行、代码块不计入。 |

## 2. B 段：需人眼的雷区

以下五类没有可靠的形式特征，脚本无法定位，**只出清单、不判错、不计入问题计数**。

### B1 逻辑跳跃

| 项 | 内容 |
|---|---|
| **为什么是雷区** | 前提与结论之间缺一环，读者必须自己补。补不出来就是论证不成立，补得出来也会因各家补法不同而产生歧义。 |
| **典型示例（占位符）** | 前：「<模型 M> 的表现优于 <基线 C>。<方法 X> 有效。」——中间缺「为什么更好的表现能推出方法有效」这一环。 |
| **怎么改** | 补上中间环节，或把结论收窄到能被现有前提支撑的范围。 |

### B2 因果倒置

| 项 | 内容 |
|---|---|
| **为什么是雷区** | 把共同原因、选择偏倚或反向因果写成「A 导致 B」，是结论层面的根本错误，一旦被指出，整篇的可信度都会受影响。 |
| **典型示例（占位符）** | 前：「<使用 <工具 T> 的组别成绩更高，因此 <工具 T> 提升了成绩。」 |
| **怎么改** | 核对研究设计是否支持因果表述；不支持就改为相关性表述，并交代可能的混杂因素。 |

### B3 过度概括

| 项 | 内容 |
|---|---|
| **为什么是雷区** | 从单一样本、单一场景、单一任务推出的普遍化结论，是评审最常挑的一类问题，尤其是当原文用了「普遍」「一般」「总是」这类词时。 |
| **典型示例（占位符）** | 前：「在 <数据集 B> 上 <方法 X> 表现良好，因此该方法适用于所有 <任务类别>。」 |
| **怎么改** | 把适用范围收回到证据覆盖的范围；或明确写出还需在哪些场景下验证。 |

### B4 结论超出数据

| 项 | 内容 |
|---|---|
| **为什么是雷区** | 结论强度（显著、趋势、方向、机制）与底层数据（样本量、区间、不显著结果）不匹配。**未达显著不等于没有差异**，这是最常被指出的一条。 |
| **典型示例（占位符）** | 前：「<指标 A> 的 p 值为 <数值>，说明 <方法 X> 显著优于 <基线>。」——而该 p 值实际未达显著。 |
| **怎么改** | 逐条核对结论与对应结果：样本量、效应量、区间、检验方式；如实报告不显著与负结果。 |

### B5 伦理 / 利益冲突缺声明

| 项 | 内容 |
|---|---|
| **为什么是雷区** | 缺少伦理审批、知情同意、数据可得性、资助来源、利益冲突或作者贡献声明，往往直接构成投稿的硬性缺项，会被编辑部退回或要求补齐。 |
| **典型示例（占位符）** | 前：全文无「伦理审查」「知情同意」「数据与代码可得性」「利益冲突」「作者贡献」「资助」等声明段落。 |
| **怎么改** | 按目标期刊 / 会议的投稿要求补齐声明段落；确实不适用的项目写明不适用及其原因，不要留空。 |

## 3. A 段与 B 段的分工理由

| 维度 | A 段（机检） | B 段（人眼） |
|---|---|---|
| 判定依据 | 形式特征：固定短语、标点符号、符号配对、长度计数 | 论证结构与证据强度 |
| 能否自动化 | 能，且稳定可重复 | 不能：判定依赖全文语境与领域知识 |
| 误报代价 | 低：定位到行，作者一眼能确认 | 高：机器若下结论，容易给出似是而非的判断 |
| 脚本输出 | 逐条列出，带行号与级别，计入问题计数 | 只出人工复核清单，**不计数** |
| 风险 | 漏报罕见形式（如同义改写的套话） | 依赖人的时间与注意力，最容易被跳过 |

**为什么不做自动改写：** A 段里 90% 的问题「怎么改」并不唯一——同一句空话可以删、可以前置成实质信息、也可以改写成限定句，取决于段落意图。B 段更是如此。自动替换会把作者的判断抹掉，并且可能悄悄改动句子的断言强度。

**为什么 B 段不计数：** 把无法可靠判定的事项混进计数，会让「问题数」这个指标失真，反而降低它的参考价值。分开呈现，读者知道哪些是确定的形式缺陷、哪些是需要动脑的实质性风险。

## 4. 误报高发区

以下三类内容在机检中天然容易触发，脚本已做部分保护，但作者仍需人工确认。

### 4.1 引文原文

- **场景**：参考文献、他人原话、教材引用、逐字摘录的实验日志。
- **为什么容易误报**：引文里常出现「可能」「受限于」「众所周知」，它们是**原文的一部分**，不属于作者的断言。
- **脚本保护**：引号区间（「“ ”」「「 」」「""」）与行内代码区间内的匹配一律静默（保护判据 P9）。
- **仍需人工确认**：
  - 中文引号缺失、只用了斜杠或书名号代替引号的场合，区间识别不到；
  - 用 Markdown 的 `>` 引用块排版的内容，脚本按引用块处理并整段静默，需确认引用块里确实是引文；
  - 长篇直引（超过一句）即使加了引号，也可能被截断识别。

### 4.2 他人观点

- **场景**：转述前人工作、比较文献结论、复述综述中的判断。
- **为什么容易误报**：转述句里的弱化语气属于被转述者的语气（研究「也许」表明……），不是作者对自己结论的态度。
- **脚本保护**：出现文献引用标记（`[n]`）或「文献 / 前人 / 作者 + 指出 / 认为 / 主张」结构的句子，相关规则被静默（保护判据 P8）。
- **仍需人工确认**：
  - 中文写作里「某某（<年份占位>）认为……」这类无编号引用，如果作者没有用引用标记，脚本可能识别不到；
  - 转述之后紧跟作者自己的判断时（如「前人认为……，而我们发现……」），需要人判断后半句是否被前面的转述语气带弱。

### 4.3 必要限定语

- **场景**：范围限定（在本数据集上）、统计精度说明（效应量较小，未检出显著差异）、设计边界（n=… 的预实验）、条件性结论（在…条件下）、前瞻声明（后续研究将检验）。
- **为什么容易误报**：这些限定语在形式上就是弱化表达，但它们承担的是**必须承担的诚实义务**，删掉反而是问题。
- **脚本保护**：保护判据 P1–P7 命中时静默。
- **仍需人工确认**：
  - 限定语位置写错时，保护可能掩盖问题——例如把「在本数据集上」放在段末却用于修饰全段结论；
  - 限定语被过度使用时（如每句都加「在有限条件下」），脚本不会报，但读起来仍是防御性写法；
  - 中英混排文本里英文限定语（on this dataset / under these conditions）不在中文模式的识别范围内，需要人眼补充。

### 4.4 其他易误报点

| 场景 | 表现 | 处理 |
|---|---|---|
| 教学材料 / 科普文本 | 大量套话与口语连接词是风格选择 | 作者判断；脚本只出 low 级候选 |
| 表格与图注 | 短句、术语堆叠 | 逐条读一遍即可 |
| 致谢与声明段 | 「首先」「其次」是正常结构 | 一般不触发 |
| 学位论文长摘要 | 段落偏长是体例要求 | 调大 `--max-para-chars` |

## 5. 一页速查

```
A 段（机检、计数）：A1 空话 / A2 连接词 / A3 标点 / A4 数字与单位 / A5 符号不成对 / A6 段落长度
B 段（人眼、不计数）：B1 逻辑跳跃 / B2 因果倒置 / B3 过度概括 / B4 结论超出数据 / B5 声明缺失
```

- 退出码：`0` 无问题 / `1` 发现问题 / `2` 用法错误或运行故障。
- `--json` 输出里 `manual_checklist` 字段即 B 段清单，`files[].findings` 里只有 A 段问题。
- 所有示例中的尖括号均为占位符。
