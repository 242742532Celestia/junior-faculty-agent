# 防御性写作参考

本文件是 `assertive-writing` 技能的方法层说明，配合 `scripts/lint_defensive.py` 使用。

阅读顺序建议：先看第 1 节（分类）和第 3 节（保留判据），再回头跑脚本。

---

## 1. 六类功能分类表

分类依据是**句子在论证中承担的功能**，不是「弱化词清单」。同一个词在不同功能位置可以完全正当；同一个功能也可以用不同的词实现。

| 规则 ID | 功能类别 | 英文表述 | 级别 | 句子承担的功能 | 变形识别（脚本信号） |
|---|---|---|---|---|---|
| HEDGE | 过度对冲 | over-hedging | medium | 把断言强度从「证据支持的强度」往下压 | 可能、也许、或许、或可、似乎、某种程度上、一定程度上 |
| SELFDEP | 自我贬低 | self-deprecation | high | 替读者预设对本工作的负面评价 | 我们只是尝试 / 试图、仅仅是简单的方法、不足为道、这很粗糙、不值一提 |
| RESP | 责任外推 | responsibility-shifting | high | 把「本研究没做的事」归因于外部条件 | 受限于篇幅 / 数据、篇幅所限、无法进一步讨论、不再展开 |
| DISCLAIM | 先行免责 | pre-emptive disclaimer | medium | 在结论出现前先替自己免责 | 当然，这只是初步结果、我们无意……、请勿过度解读、本文只是一项初步研究 |
| AGENT | 模糊化施动者 | agent-obscuring | high | 抹掉「谁做的判断」，让主张不可追溯 | 研究显示、有研究表明、先前研究表明、学者们认为、大量研究表明 |
| SUBJ | 主观化归因 | subjective attribution | low | 用评价性副词替代论证 | 众所周知、不难发现、不难看出、显然、显而易见、不言而喻、毫无疑问 |

**六类的共同诊断**：它们都在做同一件事——**让句子的字面断言强度低于它所依据的证据**，或**让读者无法判断这句话是谁说的、依据是什么**。因此判断标准不是「像不像好文章」，而是「这句话的强度和证据的强度对不对得上」。

## 2. 保留判据（与脚本受保护逻辑一一对应）

脚本在报出候选之前会先检查保留判据。命中的匹配**不得报为问题**，只计入「受保护而静默」统计。

下表是脚本里 P1–P9 的完整清单：

| 脚本 ID | 保留判据 | 识别什么（示例均为占位符） | 可压制的规则 |
|---|---|---|---|
| P1 | 范围限定 | 「在本数据集上」「在该样本中」「在本文的数据集上」 | HEDGE、AGENT、SUBJ |
| P2 | 效应量小但差异稳定 | 「效应量较小（d=<数值>），但差异稳定」 | HEDGE、SUBJ、DISCLAIM |
| P3 | 统计不显著 | 「未检出显著差异」「p > <阈值>」 | HEDGE、SUBJ、DISCLAIM |
| P4 | 样本受限 | 「在 n=<样本量> 的预实验中」「小样本」「探索性研究」 | HEDGE、SELFDEP、RESP、DISCLAIM、SUBJ |
| P5 | 条件性结论 | 「在 <条件> 条件下」「当 <条件> 时」 | HEDGE、AGENT、SUBJ |
| P6 | 明确的未来工作声明 | 「后续研究将检验……」「有待进一步验证」 | HEDGE、DISCLAIM、RESP、SUBJ |
| P7 | 涉及他人的错误归因 | 「这一错误来自先前工作的误用」 | HEDGE、SUBJ、RESP、AGENT |
| P8 | 引用他人观点 | 「正如文献 [<编号>] 所指出的」「引述 <文献> 的观点」 | HEDGE、AGENT、SUBJ、DISCLAIM |
| P9 | 引文原文 | 引号区间、行内代码、引用块内的全部片段 | 全部规则 |

**归并成五条保留判据**（与上表一一对应，无遗漏、无重复）：

| 保留判据 | 覆盖脚本 ID | 为什么必须保留 |
|---|---|---|
| **保留一：结论有范围** | P1、P5 | 已经限定了适用范围，再削弱只会让读者无法复述结论的边界 |
| **保留二：结论有统计精度** | P2、P3 | 区分「显著」与「效应量」、如实报告不显著，是学术诚信的基本要求，不是对冲 |
| **保留三：研究有设计边界** | P4 | 写明样本量与预实验性质，是对证据强度的诚实交代 |
| **保留四：前瞻已明确** | P6 | 已声明后续工作方向，不需要再叠加模糊语气 |
| **保留五：归属已明确** | P7、P8、P9 | 在讨论他人成果或引用原文，弱化词属于转述语气与引文的一部分 |

> 重要：保留判据是**免报**机制，不是**免检**机制。作者仍然可以基于自己的判断决定改写，只是脚本不会主动催你改。

## 3. 改写流程（5 步）

### 第 1 步：标定功能

拿到一句候选，先判断它承担的是哪一类功能：

- 它在削弱断言强度吗？→ HEDGE
- 它在贬低本工作吗？→ SELFDEP
- 它在把「我们没做」推给外部吗？→ RESP
- 它在提前免责吗？→ DISCLAIM
- 它抹掉了施动者吗？→ AGENT
- 它用评价词替代了论证吗？→ SUBJ

**标定错误，后面全错。** 一句话可能同时承担多个功能——脚本会把它们合并输出并列出全部规则 ID，此时逐个标定。

### 第 2 步：判断是否该删

不是所有命中都要动。逐条问：

1. 命中的是否落在保留判据里？（P1–P9）→ 是则不改。
2. 这句话在段落里承担什么角色？如果它是**限制条件**而不是**免责声明**（例如出现在局限性段落末尾），它可能是必要的。
3. 删掉之后，句子的断言强度会变成什么？和你手上的证据一致吗？

结论只有四种：`保留` / `削弱` / `加强` / `删除`。

### 第 3 步：改写

按判断结果执行，且遵守两条硬约束：

- 只改措辞：**不改数据、不改结论方向、不补引文、不补作者与年份**；
- 每改一句，回头检查它是否仍满足第 2 节的保留判据。

改写手法按类别：

| 类别 | 手法 | 前后对照（占位符） |
|---|---|---|
| HEDGE | 用证据强度替换语气词 | 前：「<可能/也许>说明 <指标 A> 优于 <基线>」 → 后：「<指标 A> 高于 <基线>，差值 <数值 Z>」 |
| SELFDEP | 陈述实际贡献与边界 | 前：「我们只是尝试了一种简单的方法」 → 后：「本文实现 <方法 X>，用于 <任务 T>，并给出 <产出>」 |
| RESP | 把外部借口改成设计边界 | 前：「受限于篇幅，无法讨论 <现象 P>」 → 后：「本文只检验了 <假设 H>，<现象 P> 未纳入分析」 |
| DISCLAIM | 把限定与结论绑定 | 前：「当然，这只是初步结果」 → 后：「该结论限于 <条件 D>，需在 <场景 S> 中复核」 |
| AGENT | 写实施动者与材料 | 前：「研究显示 <结果 R>」 → 后：「<作者 A> 等用 <方法 X> 在 <数据 B> 上报告 <结果 R>」 |
| SUBJ | 补出被省略的论证 | 前：「不难发现 <现象 P>」 → 后：「<现象 P> 在 <条件 D> 下出现（见 <证据占位>）」 |

### 第 4 步：检查是否引入过度断言

这是整个流程最容易出错的一步。删掉对冲词之后，句子的强度可能已经超过了证据能支撑的范围。

**自查三个问题：**

1. 这句话现在的强度，我手上的证据真的撑得住吗？
2. 如果读者追问「凭什么」，我能指向具体的数据或分析吗？
3. 它是不是把「相关」写成了「导致」，把「在本数据集上」写成了「普遍成立」？

**过度断言的三种典型形态：**

- 把「可能有效」改成「有效」，而证据只是趋势性的；
- 把「与 <指标 A> 相关」改成「导致 <结果 B>」；
- 把限定词整体删掉：「在本数据集上、在 <条件 D> 下、未检出显著差异」被改成「我们证明了 <结论>」。

**一个指标不要写成一个判决**（见第 5 节）——这就是本步的核心原则。

### 第 5 步：改后复核

- 重跑 `lint_defensive.py`，确认新增 high 级候选已清零，或每一条都有保留理由；
- 重跑 `lint_redflags.py`，确认改写没有引入新的 A 段问题；
- 人工通读改动段落与相邻段落，确认前后一致：方法段说做了什么，结果段说的就是什么；
- 确认改动没有越过本技能的边界——没有新增数据、引文或结论。

## 4. 改写前后结构对照模板

用于整段改写时保持结构稳定。尖括号内为占位符。

**改前（占位符模板）：**

```
<背景句：套话或空泛铺垫>

我们只是尝试性地用了一种简单的方法，结果<可能>说明 <指标 A> 在 <数据集 B> 上优于 <基线 C>。

受限于篇幅，无法进一步讨论 <现象 P>。

综上所述，我们的方法是有效的。
```

**改后（占位符模板）：**

```
<直接进入问题：本文考察 <问题 Q>，使用 <方法 X>，在 <数据集 B> 上评估。>

在 <数据集 B> 上，我们用 <方法 X> 测得 <指标 A> 相对 <基线 C> 的差值为 <数值 Z>（<不确定性>）；该比较限于 <条件 D>。

本文只检验了 <假设 H>；<现象 P> 的机制未纳入分析，因此该结论不适用于 <范围 R>。

<结论句：<指标 A> 在 <条件 D> 下优于 <基线 C>。>
```

**结构对照要点：**

| 位置 | 改前 | 改后 |
|---|---|---|
| 段首 | 铺垫性套话 | 直接给出问题、方法、对象 |
| 核心断言 | 对冲 + 模糊施动者 | 施动者 + 测量 + 数值 + 不确定性 |
| 边界 | 外部借口 | 本研究自身的范围 + 结论不适用域 |
| 段末 | 「综上所述 + 有效性」 | 与数据一致的结论句 |

## 5. 「一个指标不要写成一个判决」

**原则**：一个指标支撑一个**判断**，不支撑一个**判决**。

- 指标是测量出来的量；判断是对证据强度的解读；判决是对普遍性、因果性或价值高下的终局认定。
- 只有一个指标时，最多只能得出一个受条件约束的判断；把它写成判决，是断言强度越界的典型形态。

**三个对照（占位符）：**

| 形态 | 写法 | 问题 |
|---|---|---|
| 指标 | 「<指标 A> 从 <基线值> 变为 <观测值>」 | 没问题，这是事实 |
| 判断 | 「在 <条件 D> 下，<指标 A> 高于 <基线 C>」 | 可以，这是有边界的判断 |
| 判决 | 「<方法 X> 解决了 <问题 Q>」「<方法 X> 是 <领域> 的最佳方案」 | 越界：把单一指标升级为普遍性 / 价值性终局认定 |

**落地检查：**

1. 这句话里除了「<指标 A>」之外，还用了几层修饰？层数越多，越接近判决。
2. 判决性词汇清单：解决、证明、彻底、颠覆、最佳、唯一、必然、证明了、足以说明、毫无疑问。
3. 命中判决性词汇时，回问：这个词背后的证据强度是什么？强度不够就换回判断形态。

## 6. 中文与英文表达差异

同一套功能分类在两种语言里的表现形式不同，不能直接套用词表。

| 维度 | 中文 | 英文 |
|---|---|---|
| 对冲的载体 | 语气副词为主：「可能」「也许」「某种程度上」「一定程度上」 | 情态动词与限定语为主：may / might / could / somewhat / to some extent / appears to |
| 自我贬低 | 常以「我们只是……」「这只是一个简单的方法」成句出现 | 更常以 humblebrag 式插入语出现：a simple approach / a preliminary attempt |
| 责任外推 | 常用「受限于……」「由于篇幅所限」直接挂在结论前 | 常用 due to space constraints / given the scope of this paper |
| 模糊化施动者 | 「研究显示」「有结果表明」「学者们认为」 | prior work shows / it has been demonstrated / researchers suggest |
| 主观化归因 | 「众所周知」「不难发现」「显然」 | it is well known that / it is obvious that / clearly |
| 排版与标点 | 全角标点、无空格分词；数字与单位间通常不加空格；百分号多写作 5% | 半角标点；数字与单位之间加空格（10 cm）；百分号与数字之间不加空格 |
| 引号规范 | 双引号“ ”用于引文，直角引号「 」用于强调；书名号《 》用于文献名 | 双引号 " " 用于引文，斜体用于文献名 |
| 破折号 | 规范写法为双破折号「——」，成对出现 | 破折号通常写作 —— 或 --，需与出版方模板一致 |

**迁移时的注意事项：**

1. **中文的「可能」有时是语法必需，不是对冲。** 例如「可能的原因是……」出现在列举里，删掉会破坏句法。做 HEDGE 判断前先确认它是修饰断言强度还是连接可能性。
2. **英文的 hedge 常与主语位置绑定**（the results may suggest），中文里更容易被处理成句尾的「……可能说明了」；改写时优先在中文里把断言主体前置。
3. **中文语境下的半角标点问题在英文写作里不存在**，但反过来的问题存在：英文稿件里全角中文标点混入同样是硬伤。A 段规则对两种语言都适用，识别的是「同段混用」而不是「必须用某一种」。
4. **单位与数字的空格规则两边不同**：英文 `10 cm`，中文 `10 厘米` 或 `10cm` 均可接受。本技能的 A4 规则按中文稿件的常见规范提出，英文稿件请以目标出版方模板为准（配合 `venue-templates`）。
5. **不要把英文的写作规约硬套到中文**。例如英文审稿偏好主动语态与第一复数，中文里的「我们」本来就常用；反之，中文里把「我们」全换成「本文」会显得生硬。

## 7. 机器层用法

### 7.1 人读报告

默认输出即为面向人的报告：按文件分组，逐条给出行号、句子、规则 ID、级别、命中片段、「为什么可能是问题」与「改写方向」。级别只表示后果大小，读法如下：

| 级别 | 读法 | 处理建议 |
|---|---|---|
| high | 优先读；这类问题在评审中容易被直接点名 | 全部逐条判断，不处理要给理由 |
| medium | 整段通读时留意，注意同类聚集 | 同一段出现多处时优先处理 |
| low | 扫一眼即可，多为删除类 | 可批量处理 |

**「受保护而静默 N 处」这一项要一并看**：它说明保护层生效了，也提示你文档里有多少弱化词其实是正当限定语。

### 7.2 喂给 LLM 的枚举块

把 `--json` 输出中的 `candidates` 数组连同规则说明一起交给模型时，**必须同时给出「机器只枚举、不下结论」这条约束**，否则模型会替作者做判定、或者直接把候选当成必须替换的字符串。

推荐的输入块结构：

```
[任务] 判断下列句子是否属于防御性表达，给出「保留 / 削弱 / 加强 / 删除」与理由。
[规则] HEDGE=过度对冲；SELFDEP=自我贬低；RESP=责任外推；DISCLAIM=先行免责；
       AGENT=模糊化施动者；SUBJ=主观化归因。
[保留判据] 命中范围限定、统计精度说明、设计边界、前瞻声明、他人归属、引文原文的句子一律「保留」。
[约束] 不要补写数据、引文或作者信息；不要虚构；改写只针对措辞。
[候选]
{"line": <行号>, "rule_ids": [...], "sentence": "<原句>", "level": "<级别>"}
```

模型输出必须逐条对应回原句与行号，人再复核一遍。**不要把模型的改写直接写回稿件。**

### 7.3 结构化输出

`--json` 的稳定字段：

| 字段 | 内容 |
|---|---|
| `files[].candidates[]` | 每条候选：`line`、`sentence`、`rule_ids`、`rule_names`、`level`、`matched`、`why`、`suggest` |
| `files[].suppressed[]` | 被保留判据静默的匹配：`line`、`rule`、`match`、`protected_by` |
| `files[].counts` | `high` / `medium` / `low` / `suppressed` 计数 |
| `total_candidates` | 全部文件的候选总数 |
| `note` | 分工声明（机器只枚举） |

字段名保持稳定，便于版本化接入流水线。

### 7.4 挂流水线

脚本在发现候选时返回退出码 `1`，无候选返回 `0`，用法错误或运行故障返回 `2`。

```bash
# 门禁：有候选即提醒人工复核
if ! python scripts/lint_defensive.py --file "$DRAFT"; then
  echo "存在待人工判断的防御性表达候选"
fi
```

**接入门禁时必须写清的三点：**

1. 退出码 `1` 表示「**有候选待看**」，不表示「论文不合格」；
2. `high` 级候选可以单独设一道更严的门（按 JSON 输出过滤 `level == "high"`），但仍需人工确认受保护情形；
3. 门禁的输出应当指向人，而不是自动改写——脚本从不写回原文。

## 8. 一页速查

```
1. 标定功能 → 2. 判断是否该删（含 P1-P9 保留判据） → 3. 改写（只改措辞）
→ 4. 检查是否引入过度断言 → 5. 改后复核（重跑脚本 + 通读相邻段落）
```

- 一个指标 → 一个判断，不是一个判决。
- 机器枚举，人做判断；脚本不写回原文。
- 所有示例中的尖括号都是占位符，必须由作者替换为真实内容。
