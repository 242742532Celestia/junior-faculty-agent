# 防御性写作与写作雷区

## 任务边界

本技能处理的是**措辞层面的强度校准**：句子在读者眼里到底传达了多强的断言，以及文本是否踩到形式上可查的写作雷区。

**在范围内：**

- 识别并定位防御性表达（defensive writing）：过度对冲、自我贬低、责任外推、先行免责、模糊化施动者、主观化归因；
- 识别可机检的写作雷区（writing pitfalls）：空话套话、无信息量连接词、标点错误、数字与单位不规范、符号不成对、段落异常；
- 为每一处候选给出「保留 / 修改 / 删除」的判断依据与改写方向；
- 改写后做一次复核，确认没有把对冲改成了过度断言。

**不在范围内（明确不做）：**

- 不判断研究结论对不对——结论是否成立由证据决定，本技能只管措辞。
- 不生成、修改、补全任何实验数据、统计量、引文、参考文献或作者信息。
- 不替代同行评审：评审意见的写法属于 `peer-review` 的范围。
- 不做自动替换：脚本永远只输出候选与方向，改写由作者执行。
- 不评价研究质量、期刊选择、基金申请策略。

## 两类问题

### 第一类：防御性表达

这类问题的共同点是：**句子的字面断言强度低于它所依据的证据**，或者**句子的措辞替读者预设了一个它不该预设的结论**。

| 编号 | 类别 | 级别 | 典型信号 | 核心追问 |
|---|---|---|---|---|
| HEDGE | 过度对冲 | medium | 可能 / 也许 / 或许 / 似乎 / 某种程度上 / 一定程度上 | 证据支持到什么强度，句子的强度就是什么 |
| SELFDEP | 自我贬低 | high | 我们只是尝试 / 仅仅是简单的方法 / 不足为道 | 你替读者做了价值判断吗 |
| RESP | 责任外推 | high | 受限于篇幅 / 受限于数据 / 无法进一步讨论 | 这是外部条件，还是本研究的设计边界 |
| DISCLAIM | 先行免责 | medium | 当然，这只是初步结果 / 我们无意…… | 限定条件是否与具体结论绑定 |
| AGENT | 模糊化施动者 | high | 研究显示 / 有结果表明 / 学者们认为 | 谁、用什么方法、做的什么判断 |
| SUBJ | 主观化归因 | low | 众所周知 / 不难发现 / 显然 | 这些词背后本该有的那半句论证 |

### 第二类：写作雷区

这类问题不涉及断言强度，而是**形式层面的可查缺陷**：读者需要额外做解码工作才能读到内容，或者文本本身不合规范。

- **A 段（可机检）**：A1 空话套话堆砌、A2 无信息量连接词滥用、A3 中英混排标点错误、A4 数字与单位不规范、A5 引号 / 书名号 / 破折号不成对、A6 段落长度异常。
- **B 段（需人眼）**：B1 逻辑跳跃、B2 因果倒置、B3 过度概括、B4 结论超出数据、B5 伦理 / 利益冲突缺声明。

两类的区别在于：A 段有可判定的形式特征，脚本能稳定定位；B 段的判定依赖论证本身，必须由人判断。**B 段只出清单，不判错，也不计入问题计数。**

## 工作流

```
机器枚举候选 → 逐条语义判断 → 改写 → 改后复核
```

### 第 1 步：机器枚举候选

运行 `lint_defensive.py` 与 `lint_redflags.py`，得到带行号的候选列表。此时**不做任何判断，也不开始改写**。

### 第 2 步：逐条语义判断

对每一条候选单独回答三个问题：

1. 这句话**实际想说什么**？（先用中文普通话复述一遍，不看原文措辞）
2. 复述出来的强度，与**证据实际支持的强度**一致吗？
3. 如果不一致，是措辞弱了、还是措辞强了、还是根本不该出现在这里？

判断结果只有四种：`保留`、`削弱`、`加强`、`删除`。**没有判断就不许进入下一步。**

### 第 3 步：改写

按判断结果执行。改写时遵循两条硬约束：

- 只改措辞，**不改数据、不改结论方向、不补引文**；
- 每改一句，回头检查它是否还满足本技能 `references/assertive-writing.md` 里的保留判据（范围、统计精度、设计边界、前瞻声明、归属）。

### 第 4 步：改后复核

- 重新跑一遍两个脚本，确认新增的高危项（high）已清零或已逐条说明理由；
- 人工通读改动段落，确认**没有把对冲改成了过度断言**——这是本流程最容易出的错；
- 确认改动没有让前后段落互相矛盾（方法段说做了、结果段说没做，是硬伤）。

## 机器与人的分工

**机器只枚举，不下结论。**

| 环节 | 谁来做 | 说明 |
|---|---|---|
| 定位候选句与行号 | 机器 | 稳定、可重复、零遗漏 |
| 判断是不是真问题 | 人 | 依赖语义与上下文，机器无法判定 |
| 决定删 / 改 / 留 | 人 | 作者责任 |
| 给改写方向 | 机器 | 只给方向，不给替换串 |
| 执行替换 | 人 | 脚本不写回原文 |

脚本报告的级别（high / medium / low）只表示**该类问题在论文中的后果大小**，不表示「这句一定错了」。high 也不等于必须改：受保护判据命中的句子会被静默处理，但作者仍可基于自己的判断决定保留。

## 判据表

改写时对每条候选使用下表。这张表与 `scripts/lint_defensive.py` 的规则 ID 一一对应。

| 规则 ID | 类别 | 级别 | 触发信号 | 保留条件（命中则不改） | 处理建议 |
|---|---|---|---|---|---|
| HEDGE | 过度对冲 | medium | 可能 / 也许 / 或许 / 似乎 / 某种程度上 / 一定程度上 | P1 范围限定、P2 效应量小但差异稳定、P3 统计不显著、P4 样本受限、P5 条件性结论、P6 未来工作、P7 他人错误归因、P8 引用他人观点 | 用证据强度替换语气词 |
| SELFDEP | 自我贬低 | high | 我们只是尝试 / 仅仅是简单的方法 / 不足为道 / 这很粗糙 | P4 样本受限 | 陈述实际贡献与边界 |
| RESP | 责任外推 | high | 受限于篇幅 / 受限于数据 / 无法进一步讨论 | P4 样本受限、P6 未来工作、P7 他人错误归因 | 写成可核查的边界说明 |
| DISCLAIM | 先行免责 | medium | 当然，这只是初步结果 / 我们无意…… / 请勿过度解读 | P2、P3、P4、P6、P8 | 把限定与具体结论绑定 |
| AGENT | 模糊化施动者 | high | 研究显示 / 有结果表明 / 学者们认为 | P1、P5、P8 | 写实施动者：谁、用什么方法 |
| SUBJ | 主观化归因 | low | 众所周知 / 不难发现 / 显然 | P1、P2、P3、P4、P5、P6、P7、P8 | 补出被省略的论证 |

**保留判据速查（与脚本受保护逻辑一一对应）：**

| 判据 | 脚本 ID | 识别什么 | 可压制的规则 |
|---|---|---|---|
| 保留一：结论有范围 | P1、P5 | 在本数据集上 / 在……条件下 | HEDGE、AGENT、SUBJ |
| 保留二：结论有统计精度 | P2、P3 | 效应量较小（d=……）/ 未检出显著差异 | HEDGE、SUBJ、DISCLAIM |
| 保留三：研究有设计边界 | P4 | 在 n=…… 的预实验中 / 小样本 | HEDGE、SELFDEP、RESP、DISCLAIM、SUBJ |
| 保留四：前瞻已明确 | P6 | 后续研究将检验…… | HEDGE、DISCLAIM、RESP、SUBJ |
| 保留五：归属已明确 | P7、P8、P9 | 错误来自先前工作 / 如文献 [n] 所指出 / 引文原文 | HEDGE、AGENT、SUBJ、DISCLAIM、RESP |

## 脚本用法

两个脚本都只用 Python 标准库，可离线运行，退出码统一：`0` 无问题 / `1` 发现问题 / `2` 用法错误或运行故障。

### 防御性表达枚举

```bash
# 检查一个或多个文件
python scripts/lint_defensive.py --file paper.md --file discussion.md

# 从标准输入读
python scripts/lint_defensive.py --stdin < paper.md

# 结构化输出（适合接流水线或喂给模型）
python scripts/lint_defensive.py --file paper.md --json

# 离线自检
python scripts/lint_defensive.py --selftest
```

输出为每条候选的：行号、句子、规则 ID、规则名、级别、为什么可能是问题、改写方向。被保留判据命中的匹配会被静默，并在统计里单列「受保护而静默 N 处」，便于确认保护层确实在工作。

### 写作雷区扫描

```bash
python scripts/lint_redflags.py --file paper.md
python scripts/lint_redflags.py --file paper.md --json
python scripts/lint_redflags.py --file paper.md --max-para-chars 240   # 段落阈值可调
python scripts/lint_redflags.py --selftest
```

输出区分严重度并给出行号；B 段清单单独成节，标注「不判定对错，不计入问题计数」。

### 挂进流水线

两个脚本在发现问题时返回退出码 `1`，可直接用作门禁：

```bash
python scripts/lint_defensive.py --file "$DRAFT" || echo "存在待人工判断的防御性表达候选"
```

注意：**退出码非 0 只表示「有候选待看」，不表示「论文不合格」**——尤其当 `high` 级候选经作者判断全部属于受保护情形时。

## 改写示范

以下示例全部使用占位符，尖括号内是需要作者替换的真实内容。**不要把任何示例里的占位符当作事实，也不要在没有证据的情况下填写它们。**

### 示范一：过度对冲 → 与证据对齐

- 改前（占位符）：「我们只是尝试性地用了一种简单的方法，结果可能说明了 <指标 A> 在 <数据集 B> 上优于 <基线 C>。」
- 改后（占位符）：「在 <数据集 B> 上，我们用 <方法 X> 测得 <指标 A> 相对 <基线 C> 的差值为 <数值 Z>（<区间或不确定性>）；该比较限于 <条件 D>。」
- 改了什么：删掉自我贬低与对冲词；补上施动者、测量方式与不确定性；把范围限定保留在句尾。
- 保留了什么：数据来源、比较对象、条件限定一项都没动。

### 示范二：模糊化施动者 → 写实来源

- 改前（占位符）：「研究显示，该方法在 <任务 T> 上显著优于已有方法。」
- 改后（占位符）：「<作者 A> 等在 <文献/数据集 B> 上用 <评测协议 P> 比较了 <方法 X> 与 <基线 C>，<指标 A> 差异为 <数值 Z>。」
- 改了什么：把无主语的「研究显示」换成可定位的来源。
- 如果查不到具体来源，**不要硬造**：改为「<已有工作类别> 在 <条件> 下报告过类似结果（见 <引文占位>）」，或直接删掉这句断言。

### 示范三：责任外推 → 写成设计边界

- 改前（占位符）：「受限于篇幅，无法进一步讨论 <现象 P> 的机制。」
- 改后（占位符）：「本文只检验了 <条件 D> 下的 <假设 H>，<现象 P> 的机制未纳入分析；相应结论不适用于 <范围 R>。」
- 改了什么：把外部借口换成本研究自身的边界陈述，并说明边界的后果。

### 示范四：写作雷区（形式层）

- 改前（占位符）：「在当今快速发展的时代,随着科技的不断进步,值得注意的是,我们提出的方法取得了 5％ 的提升。」
- 改后（占位符）：「我们提出的方法在 <数据集 B> 上把 <指标 A> 提升了 5%。」
- 改了什么：删空话（A1）、删无信息量连接词（A2）、统一全角标点（A3）、统一百分号写法（A4）。

## 常见失败模式

1. **把对冲一刀切删光。** 「可能」「也许」被当成坏词全删，结果把「在本数据集上可能略有提升」改成了普遍性断言。正确顺序是：先标定该句的功能，再决定该不该动。
2. **把统计术语当对冲删掉。** 「未检出显著差异」「效应量较小（d=……）」是结论本身，不是语气词。删掉它们等于伪造结果。
3. **拿 high 级直接当结论。** 级别表示后果大小，不表示判定结果。每一条都要自己读过上下文。
4. **先改写，后补证据。** 常见于「先让句子好看，再想办法支持」。顺序必须反过来：先确认证据强度，再写句子。
5. **只改结论段，不改方法段。** 结果段的断言调强后，方法段若还写着「仅做初步探索」，前后不一致会被审稿人直接抓住。
6. **段落拆分破坏逻辑。** A6 提示拆段，拆的时候要保证每一段是一个完整论点，而不是把一段话切成三半。
7. **误伤引文原文。** 参考文献、他人原话里的「可能」是引文的一部分。脚本对引号区间与引文行做了保护，但作者仍需人工确认。
8. **把 B 段当成脚本能查的事。** 逻辑跳跃、因果倒置、结论超出数据，脚本查不出来，却是最容易被评审抓住的。

## 与其他技能的分工

| 技能 | 与本技能的边界 |
|---|---|
| `scientific-writing` | 负责草稿撰写与证据绑定（每条事实性主张对应可核查的证据）。本技能在成稿之后做措辞强度校准，不生成内容。 |
| `peer-review` | 负责评审意见的组织与专业批评。本技能只处理作者自己稿件里的措辞，不产出评审意见。 |
| `scholar-evaluation` | 负责对已有工作本身做评估（方法、数据、可复现性）。本技能处理的是「我们自己怎么写」，不评价他人研究。 |
| `venue-templates` | 负责目标期刊 / 会议的结构与格式模板。本技能的 A 段（尤其 A3、A4）需与该模板的格式要求一并核对。 |
| `assertive-writing`（本技能） | 负责断言强度、防御性表达与写作雷区，输出候选与改写方向，不下结论、不改数据。 |
| `source-credibility-evaluation-protocol` | 负责来源可信度评估。本技能在改写 AGENT 类问题时需要它来确认「施动者」该指向谁。 |
