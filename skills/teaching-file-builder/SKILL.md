# 教学文件产出规范

## 这个技能解决什么

教学文件的麻烦不在内容，在**格式不统一**：
同一个老师， syllabus 一套格式、教案另一套、课件又是随手写的，
到期末填学院表格时全部要重排。

本技能规定**每类教学文件的必备结构**，让产出一次成型、直接可用。
**具体教学方法**（逆向设计、认知负荷、提问序列）由对应的方法技能负责，
本技能只管**文件形态与完整性**。

## 通用规则（所有教学文件）

1. **抬头统一**：课程名称 / 课程代码 / 授课教师 / 学院 / 学期 / 学时 / 适用专业 / 课程性质
   （必修/选修）/ 先修课程。用户没给就留 `____`，**不要编课程代码**。
2. **用表不用散文** —— 课时分配、目标支撑、考核权重都用表格。
3. **标注来源** —— 哪些是用户提供的，哪些是你的建议（标「建议」），哪些是假设（标「假设」）。
4. **结尾附「需人工核验清单」** —— 所有需要教师确认的项集中列出。
5. **中文正文，术语中英并列**（首次出现时）。

## 大纲先行层：先写大纲，再派生教案与课件

当一次要产出**教案 + 课件**（或再加讲义）时，**不要把它们当成两份独立文件分别写**。
先写一份**大纲**，再从它派生。

**大纲的形状**

```
meta        课程抬头
ubd         单课设计骨架（UbD 适配：大概念 / 基本问题 / GRASPS / WHERETO）
objectives  教学目标（3–5 条，每条绑定课程目标编号）
modules[]   教学模块
  steps[]   教学环节（分钟 / 教师活动 / 学生活动 / 设计意图 / 对应目标）
    slides[] 这一环节配套的页面（标题 / 要点 / 讲稿 / 来源标注）
deck        封面与目录页（不属于任何环节）
```

**四条硬约束**

1. **每页正文课件必须挂在某个环节下** —— 课件页因此永远说得清"它在讲哪一步"。
2. **每个环节要么有配套页面，要么写明为什么没有**（`no_slide_reason`）——
   区分"这一环节本来就是学生活动，不投影"与"漏做课件"。这两种成因必须分开，
   只看"页数为 0"会把前者也当成错误。
3. **时间三层闭合**：本次课分钟 = Σ 模块分钟 = Σ 环节分钟。
4. **每页课件有稳定 id**（`P1`/`P2`…）—— 增量重生成要靠它定位到"只重跑哪一页"。

### UbD 骨架：这一次课凭什么这样设计

大纲除了回答「这次课怎么讲」，还要回答**「这次课凭什么这样设计」**。
适配自 `backwards-design-unit-planner` 的 UbD 内核
（阶段一预期结果 + 阶段二表现性任务 + 阶段三覆盖检查）——
**"为什么学"是骨架，"怎么讲"是血肉，两层都要写，缺一层另一层就悬空。**

```
ubd
  big_idea[]            持久理解（1–3 条）：学生能带走、能迁移的理解
  essential_questions[] 基本问题（3–5 个）：贯穿本次课、指向持久理解的开放问题
  grasps                表现性任务六要素（G / R / A / S / P / S）
  whereto               学习循环覆盖（七项，每项写明"落在哪个环节"）
```

**持久理解（big_idea）写法**

写成「学生能理解 ___，并在 ___ 情境中用它」，**不写成**「理解 XX 原理」。

- ❌「理解直方图均衡化的基本原理」（这是知识点，且无法迁移）
- ✅「学生能理解图像增强本质是重新分配可辨识的灰度信息，并在低对比度医学影像这一情境中用它选择处理方式」

**基本问题（essential_questions）写法**

3–5 个。两条判据都要过：**无法靠背定义回答**；**课程结束时仍能回答**。

- ✅「信号在传递过程中发生了什么，哪些是信息、哪些只是噪声？」
- ❌「什么是频域？」（能靠背定义回答，且不指向持久理解）

**GRASPS 六要素**

| 要素 | 含义 | 填写要求 |
|---|---|---|
| G · Goal 目标 | 学生要达成的真实目标 | 写成委托方的要求，不是知识点 |
| R · Roles 角色 | 学生扮演的角色 | 角色决定可用信息与决策权限 |
| A · Audience 受众 | 产出给谁看 | 受众决定质量标准与表达要求 |
| S · Situation 情境 | 故事发生的处境 | 情境里必须有真实约束与利害 |
| P · Product 产物 | 学生交出的东西 | 可检验的成品，不是"参与讨论" |
| S · Standards 标准 | 质量标准 | 必须能判定达标与否（含量规/阈值） |

> 六要素写全了，这个任务才有"真实性"；缺一两项不致命，但 **P 与 S 必须实**。

**WHERETO 七项覆盖**

| 代号 | 要素 | 含义 |
|---|---|---|
| W | Where & Why | 在什么情境下学、为什么重要 |
| H | Hook | 钩子（怎么把人拉进来） |
| E | Equip | 装备（需要什么工具/知识/资源） |
| E | Experience | 体验（学生实际经历什么） |
| R | Rethink & Revise | 反思与修订（改了以后怎么办） |
| T | Tailor | 因材施教（给不同的人什么不同支持） |
| O | Organize | 组织（怎么排序、怎么分组、怎么衔接） |

> 七个要素不必各占一节课，但**每一项都要有"落在哪"的答案**（写明环节号）。
> 答不出来的项就是设计漏洞，**尤以 E·Experience 与 R·Rethink 最常漏**。

**UbD 与教学目标的两层关系**：持久理解是"为什么学"（少数几条，跨学期仍成立），
教学目标是"怎么算达成"（多条，一条对应一份证据）。
目标都要挂在持久理解下；持久理解若无任何目标支撑，多半写成了口号。

**为什么值得多这一步**

教案与课件的对齐是**结构问题**，不是**检查问题**：

- 各自写 → 改了教案忘了改课件，只能靠事后核对去发现；
- 从大纲派生 → 两边共用同一份事实源，**"对不上"这件事在结构上不可能发生**。

对齐仍然**可被检查**：检查的是"派生结果 == 重新派生的结果"，
而不是"两份文件碰巧一样"—— 后者靠不住，前者能证伪。

**判据**

| 检查项 | 判定 |
|---|---|
| 本次课分钟 = Σ 模块分钟 = Σ 环节分钟 | ☐ |
| 每个环节与模块绑定的目标都存在于教学目标 | ☐ |
| 每个环节都有教师活动 / 学生活动 / 设计意图 | ☐ |
| 每页正文课件都有讲稿，且能溯源到具体环节 | ☐ |
| 没有页面的环节都写了 `no_slide_reason` | ☐ |
| 封面唯一且在首位（章节过渡用 section，不用 title） | ☐ |
| 持久理解 1–3 条，每条写成「能理解……并在……情境中用它」 | ☐ |
| 基本问题 3–5 个，且不是能靠背定义回答的题 | ☐ |
| GRASPS 六要素齐全（至少 P 与 S 实） | ☐ |
| WHERETO 七项都写明了落在哪个环节（E·Experience 与 R·Rethink 不为空） | ☐ |

## 文件类型 1：教学大纲（Syllabus）

**必备结构**
```
一、课程基本信息（表）
二、课程简介（150–300 字：这门课解决什么问题）
三、课程目标与毕业要求支撑（表）
     课程目标编号 | 课程目标描述 | 支撑的毕业要求指标点 | 达成度评价方式
四、先修课程与适用专业
五、课程内容与学时分配（表）
     章次 | 内容 | 支撑的课程目标 | 理论学时 | 实验/实践学时 | 教学方法
六、课程思政融入点（表）
     章次 | 融入的具体内容 | 融入方式 | 承载的价值引领
七、考核方式与成绩构成（表）—— 各项占比合计必须 = 100%
八、教材与参考书（表）—— ISBN 需真实，查不到标「待补充」
九、教学方法与教学资源
十、课程目标达成度评价方式与持续改进机制
```

**易错点**
- ❌ 学时分配加起来不等于课程总学时
- ❌ 考核占比加起来不等于 100%
- ❌ 毕业要求指标点是编的（如"毕业要求 3.2"但用户没给过指标体系）→ 标「待补充」
- ❌ 教材 ISBN 是编的

## 文件类型 2：教案（Lesson Plan，按课时）

一份教案 = **一节课**。多节课时每节一份，格式相同。

**必备结构**
```
一、本次授课信息（表）
     课程 | 第几次课 | 课题 | 学时 | 授课方式 | 授课日期
二、教学目标（3–5 条，可检验）
     用可观察的行为动词（能…/会…/能够分析…），不用"了解/掌握"
     每条标注对应课程目标编号
三、教学重点与难点
四、学情分析
     先备知识、可能障碍、认知负荷预判、对应的教学应对
五、教学方法与教具
六、教学过程（分时段，含时间分配）
     时间 | 教师活动 | 学生活动 | 设计意图 | 意图对应的目标
     ⏱ 各项时间相加必须 = 本次课总学时
七、板书设计
八、课堂提问与互动设计（至少 3 个预设问题 + 预期回答 + 追问路径）
九、课程思政融入点（若有）
十、课后作业与延伸阅读
十一、教学反思要点（课后填写栏）
十二、需人工核验清单
```

**易错点**
- ❌ 教学过程只有时间没有"设计意图"——那不是教案，是流水账
- ❌ 各环节时间加起来 ≠ 总学时
- ❌ 教学目标用"了解/熟悉"这类不可检验的动词
- ❌ 教学目标与课程目标没有编号对应

## 文件类型 3：课件大纲 / 幻灯片脚本

课件**大纲**与课件**文件**是两件事：
大纲是给你做 PPT 用的脚本，PPT 文件用 `teaching-slide-builder` 自带的
纯标准库生成器产出（**不依赖**运行时内置的 `pptx` 技能 —— 那个不随本仓库分发）；
每页写什么的设计口径见 `teaching-slide-designer`。

**必备结构**
```
一、课件信息（对应哪次课、总页数、配套讲义）
二、逐页脚本（表）
     页码 | 页面标题 | 页面要点（≤5 条） | 配图/图表建议 | 讲解要点（说什么，不写什么） | 预计用时
三、关键页设计说明
     哪几页是重点页、哪几页需要动画分步呈现
四、互动点设计
     在哪几页插入提问/讨论，形式是什么
五、需人工核验清单
```

**课件设计规范（要点）**
- 一页一个中心意思，要点 ≤5 条，字数 ≤ 每条 20 字
- 图 > 字：能画图就不写段落
- 公式要有推导过程，不只给结果
- **每页标注预计用时**，加总 = 本次课学时（留 5% 给互动与机动）
- 课件不写"谢谢聆听"页占位

## 文件类型 4：讲义 / 教学材料

**必备结构**
```
一、材料说明（适用课程与章节、体例、篇幅建议）
二、正文
     概念 → 为什么重要 → 怎么建立直觉 → 精确定义 → 例题 → 常见误区 → 小结
三、练习题（含答案与提示）
四、进一步阅读
五、需人工核验清单
```

**原则**：讲义是**自学者可独立使用**的材料，不是课件的文字复制。
每个概念必须给出「直觉 → 形式化」的桥梁。

---

## 文件类型 5：板书设计

```
一、板书主题与形式（主板书 / 副板书）
二、板书布局图（用文字框图表达位置关系）
三、板书演进顺序（分步写：先写什么，后写什么，哪些擦掉）
四、保留项说明（哪部分留到下课，供学生抄写）
```

板书要**体现推导关系**，不是条目罗列。

---

## 文件类型 6：课程思政融入点

**必备结构**
```
一、融入原则（自然融入 > 显性标注；重在学科逻辑，不贴标签）
二、逐章融入点（表）
     章次 | 融入的内容 | 融入方式 | 具体话术/案例示例 | 承载的价值引领 | 落点
三、避免的做法（反面清单）
```

**判据**：一个合格的融入点，**拿掉那句话后课程内容会缺一块**。
如果去掉后毫无影响，说明是硬贴的标签，重做。

**融入方式可选**：案例引入 / 问题导入 / 价值讨论 / 学科史脉络 / 工程伦理情境 / 科学精神与科学方法。

## 文件类型 7：课程目标—毕业要求支撑矩阵

```
一、毕业要求指标点清单（用户提供的原文；未提供则整表标「待补充」）
二、支撑矩阵（表）
     毕业要求指标点 | 指标点描述 | 支撑的课程目标 | 支撑课程内容 | 达成度评价方式 | 支撑强度（强/中/弱）
三、反向检查（表）
     课程目标 | 对应的毕业要求指标点 | 是否充分支撑
四、需人工核验清单
```

**反向检查是关键**：不仅要看每个指标点有没有课程支撑，
还要看**每个课程目标是否都指向了某个指标点**——
指向不了的目标通常是"凑出来的目标"，应提示用户删减。

## 交付前通用自检（逐条打勾）

| 检查项 | 判定 |
|---|---|
| 抬头字段齐全；用户未提供的留空而非编造 | ☐ |
| 表格化的部分用了表格 | ☐ |
| 用户提供 / 建议 / 假设 三者已区分标注 | ☐ |
| 学时合计 = 课程学时 | ☐ |
| 考核占比合计 = 100% | ☐ |
| 教学目标可检验（用行为动词）且编号对应课程目标 | ☐ |
| 教学过程含设计意图，且时间分配完整 | ☐ |
| 课程思政融入点通过「拿掉是否影响内容」检验 | ☐ |
| ISBN / 学分号 / 指标点编号等事实项真实或标「待补充」 | ☐ |
| 附「需人工核验清单」 | ☐ |
| 文档已生成实际文件（非仅 Markdown） | ☐ |

## 交叉技能

- 逆向设计与目标对齐 → `backwards-design-unit-planner`
- 量规 → `criterion-referenced-rubric-generator`
- 命题 → `exam-question-bank`
- 提问与讨论 → `socratic-questioning-sequence-generator`、`hinge-question-designer`
- 认知负荷 → `cognitive-load-analyser`
- 格式生成 → 全局 `docx` / `pdf` 技能；幻灯片用 `teaching-slide-builder` 的自研生成器
- 高校语境映射 → `references/he-context-adapter.md`
