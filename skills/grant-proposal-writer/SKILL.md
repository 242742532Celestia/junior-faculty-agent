# 项目申报书撰写（中文高校语境）

## 这个技能解决什么

中国高校教师每年要写的项目申报书有固定的评审逻辑：评审人先看**科学问题**，
再看**研究基础**，最后看**你能不能做成**。本技能把这套逻辑变成一条可执行的写作流水线。

**上游 `nature-proposal-writer` 是通用提案写作**，没有中国基金的形式要件（申报书编号、
预算表格式、立项依据的写法、结题指标）。本技能是**中文高校专用适配层**：
它决定**结构与措辞**，内容素材仍可调用 `nature-proposal-writer` / `researchwrite` / `citation-audit`（逐条引用核验）。

## 先确认这四件事（缺了就问，不要瞎填）

1. **申报书类别与指南** —— 国自然青年/面上/重点？省基金？校级？横向？
   **不同类别的篇幅、栏目、评审口径差别极大。**
   → 需要用户提供：申报指南原文或至少类别名称。
2. **申请人真实信息** —— 职称、学位、出生年月、依托单位、已获项目、代表作。
   **这些一律要用户提供或从其提供材料中抽取，不许推测。**
3. **真实研究基础** —— 实验室/平台条件、团队成员与分工、已发表论文清单。
4. **经费与周期** —— 研究周期（通常 3–5 年）、预算额度。

如果用户只说「帮我写个申报书」而这些都没给：
**先做一份"框架 + 待填清单"**，明确标出每处需要用户提供什么，
不要写出一份看起来完整但事实全是编的申报书。

## 申报书骨架（中国高校通用）

> ⚠️ 栏目名称随指南变化。输出时以**用户提供的指南**为准；下面是常见结构，
> 标 `【按指南调整】` 的地方必须提示用户核对。

### 一、立项依据（约 2000–4000 字）

这是**评审人读得最仔细的部分**，也是最容易被写坏的部分。

必须包含：
1. **研究背景** —— 领域在解决什么问题，为什么现在重要。
   带上具体的**数字/事实**（市场规模、发病率、能耗数据），并标注来源。
2. **国内外研究现状与不足** —— 不是罗列文献，而是**指出"大家做了什么、还缺什么"**。
   关键：**不足必须导向你的研究问题**，不能停在"还有待深入研究"。
3. **本项目的科学问题与研究意义** —— 用一句能被复述的话把核心问题说清楚。
   评审人看完这一句应该知道你打算干什么。
4. **研究思路与拟突破的创新点** —— 3–5 条，每条一句话，
   格式建议：「提出……，揭示……，建立……」。

**禁止**：
- ❌ "国内外学者对此进行了大量研究"这种无信息量过渡句
- ❌ 只讲重要性不讲具体缺口
- ❌ 编造"已有研究证明 X"——每条已有研究结论都要能追到具体文献

### 二、研究目标与研究内容

- **研究目标**：3–5 条，可检验、可交付（对应后面的预期成果）。
- **研究内容**：把目标拆成子任务，编号 1.1 / 1.2，与目标一一对应。
  **每条研究内容都要能回答"做完之后多知道什么"。**
- **拟解决的关键科学问题**：单独成节，1–3 条。
  判据：换个人看完这条，应该知道要解决什么、怎么算解决了。

### 三、研究方案与技术路线

- **总体思路**：一段话讲清逻辑链。
- **技术路线图**：用 `markdown-mermaid-writing` 或 `scientific-schematics` 画流程图。
  **必须有图**，纯文字的技术路线在评审里很吃亏。
- **研究方法**：按子任务分述，关键方法说明为什么选它。
- **可行性分析**：针对每个子任务说"为什么这个团队能做"，
  呼应「研究基础」一节，不要空喊"我们团队实力雄厚"。

### 四、创新点

3–5 条，每条格式：**「与已有工作相比，本项目……」**
必须能对应到立项依据里指出的"不足"。
如果一条创新点在立项依据里找不到对应的缺口，就是自己编的。

### 五、研究基础与工作条件

- **前期工作积累**：按时间线列已发表论文、已授权专利、已结题项目，
  **每条标注它支撑本项目的哪个子任务**。这一栏是评审人判断"你能不能做成"的主依据。
- **工作条件**：实验室、仪器设备、计算资源、已有的数据/样品。
- **团队结构**：成员分工与投入工时，写明谁负责什么。
- **经费预算**：按科目（设备费、材料费、测试化验加工费、差旅、劳务、间接费用）列，
  **合计必须等于申请总额**。

### 六、年度研究计划与预期成果

- **年度计划**：按年（第一年 / 第二年 …）列，标注每年要完成的**具体交付物**。
- **预期成果**：论文（数量与层次）、专利、软件著作权、报告、标准、技术路线。
  **不要写"发表高水平论文若干篇"**——写清楚几篇、投什么方向、什么时候出。

### 七、研究方案中"不写什么"

中国基金申报书的常见雷区：
- ❌ **前期基础与本项目内容重复**——前期基础写"我们已经做完了"，那本项目还做什么
- ❌ **研究内容太大**——一个项目做 5 个大方向，必然做不完
- ❌ **创新点与立项依据脱节**
- ❌ **技术路线没有图**
- ❌ **预算合计不等于申请额**
- ❌ 把**综述写成文献罗列**（堆 50 篇文献不分析，等于没写）

## 写作纪律

1. **不编造**——文献、数据、团队成员、项目号、仪器型号一律不许编。
   查不到标「待补充」，并进「需核实清单」。
2. **引用必须可追溯**——用 `citation-audit`（逐条引用核验）/ `nature-ref-verifier`
   核实每条文献的题名、作者、年份、期刊、DOI。查不到就不写进正文。
3. **数字必须能追到出处**——"市场规模 500 亿"这种要么给来源，要么删。
4. **一篇只讲一件事**——不要在一个申报书里同时塞检测、机理、算法、应用四个故事。
5. **写完自检**：见下方检查表，**逐条打勾或写"不适用"**，不允许留空。

## 交付前自检表（必须出现在交付说明里）

| 检查项 | 判定 |
|---|---|
| 创新点每条都能对应到立项依据指出的具体缺口 | ☐ |
| 研究目标、研究内容、预期成果三者一一对应 | ☐ |
| 关键科学问题可被"怎样算解决"检验 | ☐ |
| 技术路线**有图** | ☐ |
| 预算各科目合计 == 申请总额 | ☐ |
| 前期基础每条都标注了支撑哪个子任务 | ☐ |
| 所有文献可追溯（作者/年份/期刊/DOI 已核实） | ☐ |
| 所有数据与事实有来源或标「待补充」 | ☐ |
| 年度计划每年有具体交付物 | ☐ |
| 全文无「若干篇」「大量研究」等空话 | ☐ |

## 输出格式

```
一、需你提供的信息（缺项清单）—— 按优先级排，标出缺了会卡住哪一节
二、立项依据（含 2-3 条创新点，每条注明对应缺口）
三、研究目标与研究内容（目标-内容-成果对照表）
四、研究方案与技术路线（含路线图）
五、研究基础与工作条件（含经费预算表）
六、年度计划与预期成果
七、需人工核验清单（所有标「待补充」处 + 已核实但建议你复核的引用）
八、自检表（逐条打勾）
```

## 交叉技能

- 文献核实 → `citation-audit`（逐条引用核验）、`nature-ref-verifier`
- 路线图 → `markdown-mermaid-writing`、`scientific-schematics`
- 统计与功效 → `statistical-analysis`、`uncertainty-and-units`（功效/样本量计算本仓库不含，标「待计算」）
- 实验设计 → `experimental-design`
- 通用提案结构 → `nature-proposal-writer`、`researchwrite`（本机全局技能，不随本仓库分发）
- 参考文献格式 → `paper-format-adapter`（本机全局技能）
