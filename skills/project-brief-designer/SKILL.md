# 项目任务书（Brief）设计

## 这个技能解决什么

"请每位同学就××问题做一个分析报告，下周四交，字数不少于 3000 字。"
这是绝大多数高校大作业的真实指令，它把 90% 的难度留给了学生自己猜：
要做多深？交报告还是报告加代码？怎么算做对了？几个人一组、分工怎么算成绩？数据从哪来？
任务书越含糊，产出差距就越取决于"谁更会猜老师心思"而不是"谁更会做这件事"，浪费掉最有价值的能力训练。

一份合格的任务书要同时做到三件事：**像真实委托一样说清约束**（学生学会在约束下做决策）、
**验收标准可核对**（老师不必凭印象打分）、**工作量与课时匹配**（学生能真正投入）。

## 什么时候用 / 什么时候不用

**用**：
- 设计期末大作业、课程项目、毕业设计的前期任务书
- 现有大作业"题目太笼统、学生产出参差不齐"，需要收紧
- 团队作业需要明确分工规则、评分口径与防搭便车机制
- 想让学生接触真实数据与真实交付物，或把"研究题目"改成"可交付的项目"

**不用**：
- 单次课堂练习题（用 `practice-problem-sequence-designer`）
- 只是安排课程进度与章节顺序（用 `scope-and-sequence-designer`）
- 纯理论综述作业、一次性的读书报告或小论文（套 brief 结构无意义）
- 已经成熟、沿用多年的作业（只做约束核对，不必重写）

## 输入

**必填**（缺任何一项就停下来问，或先出草稿并把假设标出来）：
1. 课程名称、代码、学分、课程目标清单（编号）
2. 本作业对应哪些课程目标（**必须是可观察动词的目标**，否则先改写目标）
3. 产出物形式（报告 / 报告+代码 / 演示 / 实物原型 / 数据集 + 报告）
4. 可用课时与时间窗（例：本课剩余 4 学时课外 + 2 周）
5. 是否分组（人数、是否允许跨班、是否允许换人）

**选填**（用户没给就留空并列入"需人工核验清单"，**不许编**）：
6. 可提供的真实数据集或案例来源（**没有就写「待补充」，不要编造数据集名称或链接**）
7. 评分量规（若已有量规，brief 直接引用；若没有，标"待补"并与量规技能衔接）
8. 选题范围与模板要求（是否允许自选题目、封面/页数/文件命名/提交系统）
9. 本作业在总评中的权重（**未给就留空**）与毕业要求指标点编号（**院系给定，没给就留空**）
10. 是否涉及企业数据、涉密项目、知识产权归属，以及学术诚信与 AI 工具使用规定

## 执行步骤

1. **从目标倒推产出物，而不是从题目正推产出物。**
   对每条被覆盖的课程目标问："要证明学生达成了这条目标，他必须交出什么东西？"
   答案就是产出物——通常比"写一份报告"具体得多（如一份带敏感性分析的可行性备忘录）。
2. **写"客户委托"式的情境。**
   用 1 段话交代：你是谁、为谁做（利益相关方）、要解决什么决策问题、失败的后果是什么。
   情境不是装饰，而是让"取舍"变得有代价——学生必须自己判断什么可以妥协。
3. **把交付拆成可验收的组件。**
   每个组件写清：交付物名称、形式（页数 / 文件 / 演示时长）、技术规格或内容要求、
   验收标准（可核对：数值、条数、覆盖项、约束项清单）、占该作业成绩的比例。**比例合计恰好 100%。**
4. **设约束清单。** 至少覆盖四类：**资源**（时间、算力、数据可得性）、**技术**（工具、模型、格式）、
   **情境**（预算、规模、真实业务规则）、**制度**（合规、隐私、知识产权、学术诚信）。
   约束分"硬约束"与"软约束"两级，硬约束不可协商、违反即不合格。
5. **排里程碑并预留失败点。**
   里程碑按周给出，每个都写明交付物与检查方式（提交 / 演示 / 口头汇报）。
   必须显式设计**一个"允许失败"的中间节点**（如"方案评审会，允许推翻重来"），
   否则学生把赌注全压在截止日，过程质量无法干预。
6. **写清团队规则与个人证据。**
   分组时：分工落到具体组件、提交个人贡献说明、约定互评与换组规则，
   并写明"搭便车"的判定与后果（引用学校相关规定，不自造处分）；不分组时写明个人独立完成的部分。
7. **加真实感细节与学术诚信条款。**
   真实感细节包括数据来源真实性要求、抽样与不确定性说明、引用与致谢规范、行业格式惯例。
   AI 工具使用条款按**学校现行规定**写（允许范围、是否声明、如何处理），**不自行发明规定**；
   规定未提供时写"按学校现行学术诚信规定执行（待确认具体条款）"。
8. **做一次"学生视角"预演。** 自问三问：学生读完知道要交什么吗？知道怎么判断自己做够了吗？
   知道遇到困难该找谁、什么时候截止吗？任一为否，回去补任务书。
9. **先澄清、后放行、再动笔。** 正式写任务书之前，先走下面的「澄清轮次与确认门」：
   2–3 轮澄清把欠定需求补齐 → 把完整结构摆给用户看并拿到明确放行 → 才开始写正文。

## 澄清轮次与确认门

任务书最常见的失败不是写得不细，而是**写得太自信**：一句题目定下了主题，剩下"做多深、几个人、什么形式、怎么算对、怎么验收"全是教师心里没写下来的假设。本节处理"在动手写之前先把需求问清楚、并请用户放行"这一环。

### ① 为什么需要两轮（澄清不是问卷）

一份任务书的需求几乎总是**欠定**的：一句话的题目定下了主题，剩下的"做多深、几个人、什么形式、怎么算对、怎么验收"全没定。**在欠定需求上直接写任务书 = 替学生猜老师的意图**，而任务书本该消除猜测。

### ② 澄清轮次的做法（2–3 轮，每轮一个明确主题）

- **第 1 轮 · 落地位置**：学习者是谁（完全零基础 / 有别的语言经验 / 混合水平）、学完要拿出什么（自己的一份能跑的东西 / 一场要过的考试 / 一个能拿去开会讲的概念）。
- **第 2 轮 · 形状**：**选项必须由第 1 轮的回答长出来**。第 1 轮答"零基础" → 第 2 轮才问"案例领域偏好：生活化小工具 / 办公自动化 / 小游戏"；第 1 轮答"平时写 Java" → 第 2 轮才问"从与 Java 的差异切入还是从语法重讲"。
- **第 3 轮 · 边界**：**只在边界真的是边界时才问**（已有教材 / 大纲要不要作为来源；检查密度：每课一测 / 只期末一测 / 不测）。若两个问题都不会改变方案，**跳过这轮**。

每轮最多 **3 个大问题**。一轮塞 6 个问题 = 问卷，不是对话。

### ③ 每轮的三条硬规则

1. **每轮开头先说明"我从上一轮取用了什么"**——让用户看见他的回答被用了。不消费上一轮答案的一轮 = 换皮问卷。
2. **绝不问你已经知道的**。请求里已定、或你能安全默认的，**替用户做决定并声明出来**，让用户推翻即可（"默认中文讲授、每课 30 分钟，要改直接说"）。这不消耗任何一轮。
3. **2–3 轮，不是 4 轮**。下一轮没有承重问题时直接进确认门。

### ④ 确认门（Gate）

- **在写出任何交付物之前**，把任务书的**完整结构**摆给用户看，再请他明确放行。
- 确认门**单独一轮**，不并进澄清轮——因为在答案还没拿到之前提的方案是建立在猜测上的。
- 摆出来的内容必须包含：任务书标题与**交付物清单**、每条交付物一行说明（是什么 + 学完能干什么）、**你替他做的决定**（打分标准、形式、篇幅、组队方式——这些他可能有不同意见）。
- **沉默或含糊的回答不算放行**。他改了什么，就展示修订后的清单**再确认一次**——第二次确认比做错七周便宜得多。
- 放行之后**不要每件小事都回头再确认**；只在真的改变了任务书结构时才回头。

### ⑤ 澄清轮次记录必须留档

每轮问了什么、用户答了什么、你据此替用户定了什么，都要能填进任务书的"输入假设表"（表 9）——这样别人接手时看得见哪些是用户说的、哪些是你判断的。

### ⑥ 一条反面判据

把问题写在正文里问，**不等于问了**。用户拿不到答案表单，只拿到一个以问号结尾的段落。正确做法是**用提问工具 / 选项式问卷发起确认**，问题本身不要先在正文里预告一遍。

## 长上下文纪律

一个学期的任务书 + 多个班 + 多轮修改，全部内容都留在上下文里，会同时造成两件事：**真正重要的信息被淹没**，以及**每轮多消耗的上下文反过来降低后续质量**。

### ① 三条规则

- **每件交付物写完只留一段 3–4 句的小结**：这轮定了什么、下一轮从哪儿接。**不重放**工具细节、编号、已经总结过的方案。
- **需要细节就回读文件**，不靠重复维持。回读归档的产出（已定稿的任务书、已有的评分口径），而不是让它们一直活在对话里。
- **归档件是唯一事实源**：凡是要复用的东西（澄清记录、任务书定稿、评分口径、AI 使用条款版本）都落到文件里，对话里只留指针（文件名 + 版本号）。

### ② 配套做法

- 任务书定稿后立即写入归档位置并标版本号（如 brief-v1、brief-v2），后续修改基于归档件，而不是基于对话历史。
- 多班并行时，各班的差异只写在差异表里，共用部分只存一份，不为每个班重抄一遍正文。

## 中国高校语境要点

- **学时约束**：1 学时 = 45 分钟；2 学时连堂 = 90 分钟。大作业的课外工作量应与学分相称
  （经验值：1 学分课程大作业约 20–30 小时），任务书里要写"预计投入小时数"，否则学生普遍低估、最后赶工。
- **权重与等级**：本作业若计入总评，权重与等级→分数映射由**考核方案**给出，
  任务书内各交付物权重合计**恰好 100%**。
- **评价制度**：大作业是形成性与终结性结合的证据来源；任务书中至少设 1 个形成性节点
  （方案评审、初稿反馈），并写明该反馈是否计入成绩。
- **毕业要求支撑**：指标点编号**由院系给定**；用户没给就留空并标「待补充」，不自行编写编号。
- **课程思政**：融入点写在情境与取舍要求里（"方案须说明对利益相关方的责任取舍"），
  并注明是否进入验收标准；不写"提升家国情怀"这类不可验收的表述。
- **数据与合规**：涉及个人信息、涉密数据、企业数据时必须写明来源与合规边界；
  没有合规数据源时明确写"使用合成数据并在报告中声明"。
- **教材与团队**：任务涉及的方法需对应教材真实章节，ISBN 查不到写「待补充」；
  多数院校对分组作业有成绩构成规定，未提供时写「待确认」，不自行设定政策。
- **AI 工具**：按学校现行规定写，不自创条款；规定缺失时按上述"待补充"处理。
- **确认门与学院审批的关系**：若学院对任务书另有审批流程（如大作业须学院备案），
  **以院系流程为准**；本技能的确认门只替代"学生猜老师心思"这一层，**不能替代行政审批**。
- **记录的去向**：澄清记录与输入假设表要能贴进教学文件作为"设计依据"，
  但**不作为学生版任务书正文**（学生只该看到定稿）。
- **定稿留档**：任务书定稿的**版本号与留档位置**要写清（如 brief-v2，存于课程教学文件目录），
  后续修改基于归档件进行。

## 易错点

- ❌ 题目写成研究题目而非委托 → ✅ 写成"你是××，为××方解决××决策问题"
- ❌ 只写"交一份报告" → ✅ 拆成交付物表，每项写形式、规格、验收标准与权重
- ❌ 验收标准写"质量好""分析深入" → ✅ 换成可核对项（条数、覆盖项、独立证据数）
- ❌ 交付物权重凑整，或 brief 里另设一套评分体系 → ✅ 合计恰好 100%，评分权重与量规引用考核方案
- ❌ 不写约束 → ✅ 至少覆盖资源、技术、情境、制度四类，标硬/软
- ❌ 里程碑全是"提交" → ✅ 设一个允许失败的中间节点（评审 / 推翻重来）
- ❌ 分组只说"自行分工" → ✅ 分工落到具体组件 + 个人贡献证据 + 互评规则
- ❌ 编造数据集名称，或自己发明 AI 使用规定 → ✅ 数据源查不到写「待补充」；AI 条款依学校现行规定
- ❌ 提交只写"下周四" → ✅ 精确到日期时间，并写答疑渠道与问题截止时间
- ❌ 直接写任务书、不问需求 → ✅ 先走 2–3 轮澄清，再过确认门，然后才动笔
- ❌ 一轮塞六个问题 → ✅ 每轮最多 3 个大问题，一轮只讲一个主题
- ❌ 第 2 轮的选项与上一轮答案无关 → ✅ 选项必须从上一轮的回答长出来
- ❌ 问用户已经告诉过的事 → ✅ 替用户做决定并声明出来，让他推翻即可
- ❌ 确认门并进澄清轮 → ✅ 确认门单独一轮，且在写出任何交付物之前
- ❌ 把沉默或"嗯"当放行 → ✅ 只认明确答复；用户改了内容就展示修订版再确认一次
- ❌ 把问题写在正文里就算问过了 → ✅ 用提问工具 / 选项式问卷发起确认，正文不预告问题
- ❌ 每轮重复粘贴全部上下文 → ✅ 每件交付物只留 3–4 句小结，复用内容回读归档件

## 自检清单

- [ ] 每个交付物都能追溯到至少一条课程目标
- [ ] 情境包含角色、利益相关方与失败后果
- [ ] 每个交付物有可核对的验收标准（不是形容词），且权重合计 = 100%
- [ ] 约束覆盖资源、技术、情境、制度四类，硬软分级
- [ ] 里程碑含至少一个允许失败的节点
- [ ] 团队规则落到具体组件，含个人贡献证据要求
- [ ] 数据来源真实可获取，或明确声明使用合成数据
- [ ] 学术诚信与 AI 使用条款依学校现行规定，无自创条款
- [ ] 提交格式、命名、截止时间精确到日期时间
- [ ] 预计投入小时数与学分匹配
- [ ] 毕业要求编号、权重、量规、数据源等缺失项已列入待补充，无编造
- [ ] 已做过一次"学生视角"三问预演
- [ ] 做了 2–3 轮澄清，每轮比上一轮更窄
- [ ] 每轮开头说明了"我从上一轮取用了什么"
- [ ] 每轮不超过 3 个大问题
- [ ] 第 2 轮及以后的选项由上一轮回答长出来
- [ ] 已知信息替用户做了决定并声明出来
- [ ] 确认门单独一轮，且发生在写出任何交付物之前
- [ ] 放行拿到了明确答复，沉默与含糊不算放行
- [ ] 用户提出修改后，展示修订版并再次确认
- [ ] 澄清轮次记录与输入假设表已留档
- [ ] 守住了长上下文纪律（每件交付物只留 3–4 句小结，复用内容回读归档件）
