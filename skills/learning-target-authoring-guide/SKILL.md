# 课程目标书写与毕业要求支撑

## 这个技能解决什么

教学大纲里的目标段落，几乎总是长这样：

> "通过本课程的学习，使学生掌握……的基本原理，理解……的内在规律，
> 熟悉……的分析方法，掌握……的工程应用。"

这段话读起来顺，但没有一个词可以被检验。"掌握""理解""熟悉"无法回答三个必答问题：
学生**做什么**能被看出来？**在什么条件下**做？**做到什么程度**算达成？
于是目标段落与考核之间没有可核验的接口，支撑矩阵只能靠"老师觉得相关"来填，
专业认证材料的证据链也就撑不住。

更麻烦的是**毕业要求指标点**。指标点编号由院系与专业认证材料给定，是外部输入，
课程教师不能自己编。实际工作中常见的两种失败：老师凭印象写"毕业要求 3.2"，
编号是编的，评审一核就穿帮；或者老师干脆留空，矩阵里一片"待补充"，评审看到的是"未完成"。

本技能给出的是：**目标怎么写才能被判定**，以及**在指标点缺失时矩阵该怎么写才既诚实又可用**。

## 什么时候用 / 什么时候不用

**用**：
- 新开课 / 修订教学大纲，要写课程目标段落
- 现有目标全是"理解、掌握、熟悉"，需要改成可核验写法
- 填课程目标与毕业要求的支撑矩阵（工程教育认证、专业认证材料）
- 目标与考核对不上，需要重新界定目标边界
- 课程目标要上报教学委员会审定

**不用**：
- 已经写好的目标只是改排版
- 章节级别的教学活动安排（用 `scope-and-sequence-designer`）
- 单个单元的目标倒推（用 `backwards-design-unit-planner`）
- 毕业要求指标点本身的制定（那由学院与专业认证标准给定，不在教师职责内）

## 输入

**必填**（缺任何一项就停下来问，或先出草稿并把假设标出来）：
1. 课程名称、代码、学分、学时、课程性质（必修 / 选修 / 专业核心）
2. 课程定位与先修课程关系（这门课承接什么、后续什么依赖它）
3. 学生层次与专业背景（大一 / 大三 / 研究生；跨专业与否）
4. 院系给定的**毕业要求指标点**（编号 + 原文）；**这是外部输入，用户没给就留空**

**选填**（用户没给就留空并列入"需人工核验清单"，**不许编**）：
5. 现有大纲的目标原文（用于整改而非从零写）
6. 本课程在本轮考核中承担的任务类型（认知 / 应用 / 技能 / 情感态度）
7. 课程思政的既定要求（学校 / 学院是否有明确指定文件）
8. 教材版本与 ISBN（查不到写「待补充」）
9. 课程在专业培养方案中的"主要支撑 / 次要支撑 / 不支撑"定位（若院系已定）

## 执行步骤

1. **先做目标的可判定性体检。** 把现有目标逐条读一遍，给每条标一个判定：
   **可判定**（能写出"用什么证据算达成"）、**半可判定**（能看出学什么，但说不出做到什么程度）、
   **不可判定**（只有"理解/掌握/熟悉/了解/认识/体会"）。
   不可判定的必须重写；重写不出来的，往往说明它其实是**内容描述**而不是目标，
   应移到"教学内容"段落，不占目标名额。
2. **按三要素重写每条目标。** 格式固定为：**［可观察动词］＋［对象/内容］＋［条件］＋［程度判准］**。
   - **动词**：从修订版布鲁姆分类里取（记忆、理解、应用、分析、评价、创造），
     必要时用"设计""论证""诊断""实施""比较""解释"等更具体的动词。
   - **对象**：学生处理的具体内容，不能是"基本原理"这种泛指。
   - **条件**：在什么情境下、给定什么条件下完成（"在给定的三组实测数据下……"）。
   - **程度**：可判定的门槛（"至少指出两条独立证据""全部约束项均被覆盖"）。
   **程度判据是三要素里最常被省略、也最关键的一项。**
3. **控制目标条数与层级分布。** 一门 2 学分课通常写 4–8 条目标；
   层级上以"理解"到"应用"为主体，"分析/评价/创造"按课程定位取 1–3 条。
   层级越高，配套考核证据越难写，层级虚高会让后续所有支撑都落空。
4. **映射到毕业要求指标点。** 规则是**指标点 → 课程目标**单向追溯，不反过来改指标点：
   逐条指标点，找出本课程能**实际贡献**的目标，标注支撑强度——
   **主要支撑**（本课是该能力的主要形成环节）、**次要支撑**（提供部分证据）、
   **不支撑**（并写明理由）。一门课通常支撑 1–3 个指标点，
   反过来一个指标点往往由多门课共同支撑，**不要在一门课里写"全支撑"**。
5. **指标点缺失时按三档处理**（不编造是硬规则）：
   用户**给了编号和原文** → 直接引用，标注"来源：院系提供"；
   用户只给了**原文没有编号** → 用原文作临时标识，编号栏写「待院系补编」；
   用户**完全没给** → 指标点整列留空，表下注明
   "毕业要求指标点由院系给定，本表暂缺，待院系提供后回填"，**绝不自行编写"毕业要求 3.2"这类编号**。
   同时把"索取指标点清单"变成一条可执行的待办（谁、找谁、要什么格式）。
6. **做双向自检。** 正向：每条课程目标 → 是否被至少一个指标点或至少一个考核项覆盖；
   反向：每条指标点 → 是否有本课程目标在支撑，还是全靠别的课。
   反向检查的产出常常是**课程定位问题**，需要上报而不是在本课内部消化。
7. **标注版本与生效条件。** 目标改动涉及毕业要求支撑关系，
   须注明"待学院教学委员会审议后生效"，不要在草稿阶段写成已生效的既定事实。

## 中国高校语境要点

- **指标点来源**：毕业要求指标点**由院系与专业认证材料给定**，
  本课程教师无权制定也无权改写。用户没给就**留空并标注**，
  并把"向学院索取指标点清单"写成一条带责任人的待办。
  工程教育认证语境下，同样不得自编"毕业要求 3.2"。
- **学时与课程规模**：目标条数应与学分学时相称。1 学分课 3–5 条，2–3 学分课 4–8 条；
  学时越少越不能堆高层级目标。
- **评价制度**：目标必须能落到**形成性评价**（课堂提问、随堂小测、discussion）
  与**终结性考核**（期末笔试 / 开卷 / 机考）两类证据上；
  只有终结性证据支撑的目标，等于每学期只有一次机会判断达成。
- **权重**：若目标段落里隐含了考核权重（如"平时成绩占 30%"），
  各项必须加总**恰好 100%**；本技能不生成权重表，权重在考核方案中给全。
- **毕业要求支撑强度**：矩阵里"主要支撑 / 次要支撑 / 不支撑"三档要写全，
  一门课对同一指标点只能有一个强度标注，不许"既是主要又是次要"。
- **课程思政**：融入点挂在目标自身的论证链上（如"失效模式讨论 → 工程责任"），
  并注明是否进入考核；不写"提升家国情怀"这类不可评分的表述，不硬贴标签。
- **教材**：目标涉及的内容范围要与教材真实章节对应，ISBN 查不到写「待补充」。
- **术语**：正文中文，术语首次出现中英并列（毕业要求 / graduation requirement、
  形成性评价 / formative assessment）。

## 易错点

- ❌ 目标写"掌握 / 理解 / 熟悉" → ✅ 三要素重写：可观察动词 + 对象 + 条件 + 程度判准
- ❌ 只写动词和对象，缺"程度判准" → ✅ 没有程度的目标无法判定达成，必须补可数门槛
- ❌ 自己编"毕业要求 3.2"填进矩阵 → ✅ 指标点由院系给定；缺失就留空 + 写明待办
- ❌ 把"教学内容"写进目标段落 → ✅ 内容描述移到教学大纲的内容章节，不占目标名额
- ❌ 一门课对同一指标点同时标"主要支撑"和"次要支撑" → ✅ 一个指标点只给一个强度
- ❌ 一门课声称支撑全部指标点 → ✅ 指标点通常由多门课共同支撑，本课只写实际贡献的部分
- ❌ 只做正向映射不做反向检查 → ✅ 反向检查才能发现"本课其实没参与这个指标点"
- ❌ 目标层级虚高（全是评价/创造）却无对应证据 → ✅ 高层级目标少而精，且必须配得上证据
- ❌ 思政写成"提升家国情怀" → ✅ 落到具体案例、问题或价值讨论，并注明是否进入考核
- ❌ 目标改完直接当作已生效 → ✅ 涉及支撑关系的目标须经教学委员会审议后生效

## 自检清单

- [ ] 每条目标含可观察动词、对象、条件、程度判准四要素
- [ ] 全表没有"理解 / 掌握 / 熟悉 / 了解 / 体会"这类不可判定表述
- [ ] 内容描述已移出目标段落
- [ ] 目标条数与学分学时相称，层级分布已核对并与考核证据匹配
- [ ] 每条目标至少能挂上一类考核证据
- [ ] 指标点编号全部来自院系；缺失的留空并写了「待院系补编 / 待院系提供」
- [ ] 文档中没有任何自编的毕业要求编号
- [ ] 每个指标点只标一个支撑强度，且该强度与"支撑的具体环节"一致
- [ ] 正向、反向两向检查都做了，反向发现的缺口已单列
- [ ] 思政融入点自然且注明是否进入考核
- [ ] 教材 ISBN 真实或已标「待补充」
- [ ] 已注明目标生效需教学委员会审议

## 交叉技能

- 目标拆成可观察的小能力 → `competency-unpacker`
- 课程目标与毕业要求支撑矩阵（更完整版本） → `curriculum-crosswalk`
- 从考核证据倒推教学活动 → `backwards-design-unit-planner`
- 教学大纲与学时进度编排 → `scope-and-sequence-designer`
- 考核方案整体编排 → `assessment-design-orchestrator`
- 量规与目标的逻辑对齐 → `coherent-rubric-logic-builder`
- 目标动词层级的教学进阶安排 → `learning-progression-builder`
- 目标—活动—证据的覆盖审计 → `coverage-audit`
- 高校语境制度映射（学时、评价体系） → `he-context-adapter`
- 教学文件与大纲格式 → `teaching-file-builder`
