# 公式排版（伪公式 → 真公式）

## 这个技能解决什么

AI 写公式时几乎总是写成 Unicode 伪公式：脱字符冒充上标、下划线冒充下标、斜杠代替分式。

| 伪公式（AI 实际写出来的） | 真公式（应该长什么样） | 差在哪 |
|---|---|---|
| `x = A₀e^(−γt)cos(ω_d t + φ)` | $x = A_{0}e^{-\gamma t}\cos(\omega_{d} t + \varphi)$ | 下标是 Unicode 字符、上标是脱字符、函数是斜杠函数 |
| `c = B²L²/R` | $c = \frac{B^{2}L^{2}}{R}$ | 没有分数线，读的人得自己脑补除号在哪 |
| `√(k/m)` | $\sqrt{\frac{k}{m}}$ | 根号只盖住一半，分母还丢了括号 |
| `ω_d` | `$\omega_{d}$` | 拉丁字母 d 冒充下标 |

**两类失败，只有一类会咬人**：

- **公式写得难看** —— 教师自己看得出来，会去改。
- **公式根本没被识别** —— 排版器把 `e^(−γt)` 当普通文字印出来，
  而 `A₀` 里的下标字符在多数西文字体里**根本没有字形**，直接印成豆腐块（□）。
  这类问题**没有任何人会主动发现**，直到学生问「这个方块是什么意思」。

**根因不在渲染器，在源**：整条链路里如果源文件从头到尾没有 LaTeX，
换任何渲染器、换任何公式库都没有用 —— 渲染器只能处理已经写对的源。

## 什么时候用

**该用**：

- 用户说「公式不好看 / 公式排版 / 把公式改成真公式 / ε ω_d 看着别扭」。
- 生成讲义、教案、课件、试卷、论文、申报书之后，发现里面有伪公式。
- 要往 PPTX 里放**能双击进公式编辑器**的公式。
- 要给团队定「公式怎么写」的约定（写新内容前先定约定，成本最低）。

**不该用**：

- 纯代码里的数学计算、Matplotlib/Mathematica 出图、公式求解或符号推导。
- 文档里**根本没有公式**的一般排版任务 —— 那种情况用文档处理类 skill 或直接用 pandoc。
- 只想要一张公式图片 —— 那用 LaTeX 直接编译更快，不必走注入。

## 输入

动手之前先确认这四件事，缺哪件就问，别用假设硬上：

- **载体**：最终交付是 Markdown、PPTX、DOCX，还是只改源文件？三者的注入路径不同。
- **目标文件与范围**：改哪几份材料、哪几页。范围越具体越好（"只改第 10、11 页"优于"整个课件"）。
- **源文件能不能动**：默认**只写副本**。要覆盖原文件必须用户明确同意——讲义、课件这类教学材料
  往往有配套的构建脚本，直接改源会让下次构建把改动冲掉。
- **有没有旧的书写约定**：正文里写着「公式一律写成纯文本」「带 · 的是乘号」这类约定时，
  它和 LaTeX 约定直接冲突，改造完必须同步改掉，否则读者（和后续的 AI）会继续写伪公式。

## 执行步骤

### 1. 先判定问题在源还是在渲染器

这一步决定后面所有动作，值得花 30 秒。

在源文件里 grep `latex|katex|mathml|omml`：

```powershell
Select-String -Path 讲义.md -Pattern 'latex|katex|mathml|omml' -CaseSensitive:$false
```

零命中 ⇒ 源里根本没有 LaTeX，**问题在源**。这时换渲染器、换公式库都没有用，
必须先把源改成 LaTeX。渲染器侧只能处理已经写对的源。

### 2. 扫描：只报告，不改

```powershell
python scripts\formula_norm.py scan 讲义.md
```

🔴 上面的 `scripts\` 是**相对 skill 目录**的路径。工作目录不在 skill 目录时要用绝对路径，
否则脚本找不到：

```powershell
python <skill-dir>\scripts\formula_norm.py scan 讲义.md
```

`scan` 按规则分类报出命中（裸希腊字母、Unicode 上标、中文里夹裸变量等），
并给出每条的 suggested 写法。它的作用是**建立基线**：知道有多少处、分布在哪。

`python scripts\formula_norm.py rules` 列出全部规则类别。

🔴 **`scan` 是原始正则，没有上下文判定，会误报。** 它会把示意图箭头 `→`、
标识符 `course_code`、甚至**已经写对的 LaTeX** 里的 `^{2}` 都报成命中。
⇒ **`scan` 只能用来建立基线，不能当验收判据**；验收要用有上下文判定的
`find_spans`（见第 7 步）。

### 3. 改造：产出副本 + 逐条对照报告

```powershell
python scripts\formula_norm.py fix 讲义.md --out 讲义_规范化.md --report 讲义_对照报告.md
```

`fix` 把改造结果写进 `--out` 指定的**副本**，原文件不动；`--report` 给出逐条对照
（原文本 → 新文本 → 改写理由），改了什么、为什么改、哪条需要人工看。

改造分三层置信度：

- **A 类（整行公式）**：整段都是公式结构 → 直接改写，高置信度。
- **B 类（正文内带结构信号的行内公式）**：句子里含 `=`、`√(`、希腊字母组合等结构信号 → 改写。
- **C 类（单个裸变量）**：正文里夹的一个字母 → **只报告，不改**。误伤风险太高。

报告里带「需复核」的条目必须逐条看过再采纳。实测 227 处命中只需复核 1 处，
但那 1 处正是公式里夹了中文常量——机器改不了，只能人写。

🔴 **源里已有一部分是真 LaTeX 时，要区别对待**。工具会保留已有的 `$...$` / `$$...$$` 围栏，
只规范化内部内容，不再套第二层分隔符。但**围栏内的多行结构**（`\begin{pmatrix}`、
`\begin{aligned}`）会原样保留，不做内部改写——这类结构里的下标不会被补成 `_{...}`，
需要自己检查。

三条曾经踩过的坑（现已在脚本里修掉并设了文档级回归，但**改脚本后要跑 `selftest` 确认**）：

- 已有 `$$` 围栏被二次包裹 ⇒ 嵌套 display math ⇒ 渲染时整段公式消失；
- 已有 `$...$` 被写成 `$$...$$` ⇒ pandoc 判为字面文本 ⇒ PDF 里直接出现 `$$`；
- 代码块围栏被吞 ⇒ 代码块变成正文 ⇒ 变量名的 `_`、`*` 被转义 ⇒ 代码被改坏。

### 4. 落地验证：证明排版管线真的能渲染

改对了源，还要证明下游能出图，否则只是把问题推后。

```powershell
python scripts\formula_norm.py validate 讲义_规范化.md
```

`validate` 实测跑通：pandoc → typst 编译 PDF、pandoc → DOCX 后检查 OMML 公式数量。
这一步会真实调用外部工具；缺 typst 时该项会如实标 `skipped` 而不是假装通过。

🔴 **`validate` 返回 `ok: true` ≠ 公式是对的。** 它只验管线跑不跑得通，不验内容对不对：
一份把 `Jones 矢量` 整个吃掉、把马吕斯定律渲染成 `I = I_{0} ^2` 的坏文档，同样能 `ok: true`。

所以必须再做一次**内容级检查**——查渲染产物里有没有字面量残留：

```powershell
# typst 中间产物里的字面量残留（出现即说明公式没被识别）
Select-String -Path probe.typ -Pattern '\$\$|\\frac|\\theta|\\delta|\\cos|\_|\*' -Encoding UTF8
```

期望是 **0 处命中**。有命中就是公式没被识别（常见于嵌套 `$$`、双 `$`、代码围栏被吞）。
更稳妥的做法是把渲染出来的 PDF 转成 PNG **用眼睛看一遍**——分式有没有分数线、
上下标位置对不对，只有肉眼能判。

渲染成 PDF / DOCX。**优先用本机已有的排版 skill**（如 `markdown-export`），
它处理中文字体与版式更完整：

```powershell
node <markdown-export>/scripts/mdx.mjs convert 讲义_规范化.md --to pdf --out 讲义_规范化.pdf
node <markdown-export>/scripts/mdx.mjs convert 讲义_规范化.md --to docx --out 讲义_规范化.docx
```

没有排版 skill 时，用 pandoc + typst 直接走（本 skill 的 `validate` 就是这么跑的）：

```powershell
pandoc -f markdown -t typst 讲义_规范化.md -o 讲义_规范化.typ
typst compile 讲义_规范化.typ 讲义_规范化.pdf
pandoc -f markdown -t docx 讲义_规范化.md -o 讲义_规范化.docx
```

⚠️ pandoc 的 typst writer 对**个别命令有损**（实测 `\begin{pmatrix}` 会被压成 `vec(...)`、
`\Delta` 可能变成 `Delta`）。矩阵/对齐环境多的文档，先转 PNG 核对一下再用。

### 5. PPTX：注入原生可编辑公式

PPTX 的公式要能双击进公式编辑器，必须注入 OMML（`<a14:m>`），不能贴图片。

```powershell
# ① 先看 deck 里有哪些文本，用来写 spec
python scripts\pptx_omml_inject.py --scan 课件.pptx

# ② 按 spec 注入
python scripts\pptx_omml_inject.py 课件.pptx 课件_公式版.pptx --spec spec.json
```

spec 格式：

```json
{
  "parts": [
    {"part": "ppt/slides/slide10.xml",
     "target": "c = B²L²/R",
     "latex": "\\frac{B^{2}L^{2}}{R}",
     "prefix": "阻尼系数 "},

    {"part": "ppt/slides/slide11.xml", "auto": true},
    {"part": "ppt/slides/slide12.xml", "latex_spans": true}
  ]
}
```

- `target` + `latex`：把承载该文字的那个 run 换掉；`prefix`/`suffix` 保留公式前后的文字，
  这样「阻尼比 ζ = γ/ω₀」会变成「阻尼比」+ 真公式，而不是整句变公式。
- `auto: true`：自动检测该 part 里的**伪公式**片段并**行内**注入
  （源**未规范化**时用；片段位置由 `formula_norm.find_spans` 给出）。
- `latex_spans: true`：把 run 里 `$…$` **已经是 LaTeX 源码**的片段注入成 OMML
  （源**已规范化**时用）。

也可以整包按模式处理，不用写 spec：

```powershell
# 源已规范化：把正文页里的 $…$ 全注入成 OMML
python scripts\pptx_omml_inject.py 课件.pptx 课件_公式版.pptx --latex

# 源未规范化：自动探测伪公式并注入
python scripts\pptx_omml_inject.py 课件.pptx 课件_公式版.pptx --auto
```

🔴 **`--scope` 默认是 `slides`（只处理正文页），备注页不注入。**
理由见「中国高校语境要点」的第 4 条：讲稿必须与讲义逐字同源。

注入器自带两道守卫，注入后形状数或 XML 良构性一变就报错、不写文件：
形状被吞掉是 PowerPoint「修复」后无声删形状的前兆，坏了的文件比没有文件更糟。

### 6. 交付前把话说清楚

- **报告必须带数字**：改了多少处、复核几处、误报几处。
- **代价要说出来**：LaTeX 源在 PDF 里不再是可复制的纯文本（分式会变成排版结构），
  需要纯文本的场景从 `.md` 源或 DOCX 取。
- **视觉证据**：公式排版是视觉问题，交付对比图（改造前 / 改造后）比交付文字描述有说服力。

### 7. 本仓库的接线：所有生成物都过这一站

本仓库的**每一份生成物**（课件 / 讲义 / 教案 / 试卷 / 论文 / 申报书）都必须过一次公式校正。
不是「提示词里提醒一句」，而是**链路上的一步**：

```
                唯一事实源（大纲 / 论文提纲 / 规格）
                              │
                 ┌────────────┴────────────┐
                 ▼                         ▼
        规范化（formula_apply）      规范化（formula_apply）
        A 类 → $$…$$                 A 类 → $$…$$
        B 类 → $…$                   B 类 → $…$
        C 类 → 只报告，不改            C 类 → 只报告，不改
                 │                         │
      ┌──────────┼──────────┐              │
      ▼          ▼          ▼              ▼
   教案 md     讲义 md     课件 spec     论文 md
   （typst）   （typst）   （PPTX）
                              │
                    正文页 → 注入 OMML（真公式，可双击编辑）
                    备注页 → 保留 LaTeX 源码（讲稿必须与讲义逐字同源）
```

四个**已经踩过、不要再踩**的点：

1. **规范化只在源层做一次**。教案 / 讲义 / 课件 / 讲稿因此**必然**是同一份公式 ——
   不是「各自都改一遍、改得一样」，是「只有一份可改」。
2. **讲稿（备注页）不注入 OMML**。讲稿必须与讲义 Markdown **逐字同源**；
   注入 OMML 后备注页抽出来的是 `m:t` 里的内容（`ωd`），与讲义里的 LaTeX 源码
   （`$\omega_{d}$`）**不是同一串字** ⇒ 同源判据必红。备注页显示 LaTeX 源码，
   这是**故意的**：可读、无歧义、不破坏同源。
3. **正文页必须注入 OMML**，否则课件上会直接显示 `$\omega_{d}$` 这种源码。
4. **验收判据用 `find_spans`，不用 `scan`**。`scan` 走原始正则（无上下文），
   会把示意图箭头 `→`、标识符 `course_code` 也报成命中；`find_spans`
   才有上下文判定，**只报真公式**。用错判据 ⇒ 守卫天天误报 ⇒ 守卫等于没有。

怎么跑：

```powershell
# ① 源层规范化（派生时自动发生，也可单独跑）
python scripts\formula_apply.py spec.json --out spec.normalized.json --report 对照报告.md

# ② 公式验收闸（残留伪公式 = ERROR）
python scripts\formula_gate.py 课件.spec.json 讲义-第1次课.md

# ③ PPTX 正文页注入真公式（备注页不注入，见第 2 条）
python scripts\pptx_omml_inject.py 课件.pptx 课件_公式版.pptx --latex
```

🔴 **规范化必须幂等。** 已规范化的文本再过一次必须**一字不改** ——
派生产物会被反复重算，「讲义讲稿 ≠ 课件讲稿」是同源判据的红线。
`formula_apply.normalize_text` 的做法是：**只在确实含可转写公式时才动手**
（判据 = `find_spans`），已规范化的文本 `find_spans` 为空 ⇒ 原样返回。

🔴 **需要人工复核的改动一律中止**（不静默应用）。公式里夹中文常量这类机器改不了的，
宁可停下来报错，也不要改出一个没人看过的公式 —— 那比伪公式更危险，
因为它看起来像已经被处理过了。

## 输出模板

产出物应当包含：

| 产出物 | 说明 |
|---|---|
| `<原名>_规范化.md` | 改造后的**副本**，原文件不动 |
| `<原名>_对照报告.md` | 逐条对照：原文本 → 新文本 → 理由；标注需复核项 |
| `<原名>_规范化.pdf` / `.docx` | 验证过能出真公式的成品 |
| `*_公式版.pptx` | 注入 OMML 后的课件（如涉及） |
| 验收数字 | 命中数 / 需复核数 / 误报数 / OMML 公式数 / 字面量残留数 |

**字面量残留数**是必报项：渲染产物里若出现 `$$`、`\frac`、`\theta`、`\_` 等字面量，
说明公式没被识别（常见于嵌套 `$$`、双 `$`、代码围栏被吞）。期望 0。
只报 `validate` 的 `ok: true` 是不够的——它不验内容。

源文件被修改时，要在报告里列出**改了哪几行**，并说明为什么这次破例不覆盖。

## 中国高校语境要点

1. **中文字体里的下标字符大多没有字形**。`₀₁₂` 这类 Unicode 下标在宋体/黑体里
   经常直接印成豆腐块 —— 这不是"看着别扭"，是**信息丢失**。
   ⇒ 中文教学材料里的下标必须走 LaTeX 的 `_{...}`，不能靠 Unicode 字符。
2. **公式里夹中文常量是机器改不了的**。`\ln γ = 常数 + n·\ln(参数)` 这种，
   检测器会标出来但不会自动改（需要 `\text{}`，且要判断是否该改写），
   交回人，不要自行猜测改写。
3. **同一份 LaTeX 在 Word 与 PPTX 里长得不一样**。pandoc → docx 时 `a/b` 保持斜杠，
   **只有 `\frac` 才生成 `<m:f>`**；typst 的 math 模式则会把 `/` 直接排成真分式。
   ⇒ 要双通道都好看，源里一律写 `\frac`。
4. **讲稿与讲义逐字同源 > 讲稿里公式好看**。中文教学材料里，讲稿是要印在
   讲义上、跟着讲义一起发给学生的；两份材料里的同一句话必须一字不差，
   否则教师会讲着讲着对不上页。⇒ 讲稿页保留 LaTeX 源码（可读、无歧义），
   课件正文页才注入 OMML。
5. **课程思政与公式无关，但交付物的"排版不像真的"会削弱可信度**。
   讲义里的公式印成豆腐块，整份材料的可信度都会掉 —— 排版是形式合规的一部分。

## 易错点

| 错误现象 | 根因 | 正确做法 |
|---|---|---|
| 改造后公式整段消失 | 已有 `$$` 围栏被二次包裹 ⇒ 嵌套 display math | 工具保留已有围栏；手工改写时别再套一层 |
| PDF 里直接出现 `$$` | 已有 `$...$` 被写成 `$$...$$` ⇒ pandoc 判为字面文本 | 同上 |
| 代码块里的变量名被改坏 | 代码围栏被吞 ⇒ 变成正文 ⇒ `_`、`*` 被转义 | 工具按语言标记识别代码块；改脚本后跑 `selftest` |
| 规范化跑两遍，公式变成 `$\$…\$\$` | 已规范化的文本又被当成公式行处理 | 规范化必须**幂等**；只在确实含可转写公式时才动手 |
| 讲义讲稿与课件讲稿对不上 | 备注页被注入了 OMML ⇒ 抽出来的文本不是 LaTeX 源码 | 备注页**不注入**；只对正文页注入 |
| 注入后 PowerPoint 提示修复文件 | `a:p` 子元素顺序被破坏 ⇒ 无声删形状 | 按 `references/omml-injection.md` 的三条铁律逐条对照 |
| 满屏 `/>` | 拼 `a:rPr` 时闭合标签位置错 ⇒ 游离的 `/>` 被当字面量渲染 | 带颜色时整段拼好再闭合 |
| 守卫天天误报 `→` / `course_code` | 用了原始正则 `scan` 当判据 | 判据改用有上下文判定的 `find_spans` |
| 「A/B 类不确定度」变成 `A/B` 相除 | 类别标签被当成分式的分子分母 | 分子分母各一个大写字母 + 分母后跟类别标记字 ⇒ 不转 |
| 「停顿 2 分钟」变成「2 倍最小值」 | `min`（分钟）被映射成 LaTeX 算子 `\min` | 阈值（比较符+数值+单位）保持纯文本；`min`/`max`/`sec` 只在函数调用时才当算子 |
| 判据说「缺少关键内容」，可内容明明在 | 判据拿 Unicode 字面量去匹配**已规范化成 LaTeX** 的产物 | 判据要比**内容**不比**写法**：两边过同一份规范化器再比骨架 |

## 自检清单

改造前：

- [ ] 源文件里 grep 过 `latex|katex|mathml|omml`（确认问题在源还是在渲染器）。
- [ ] 确认了载体（Markdown / PPTX / DOCX）与范围（哪几份、哪几页）。
- [ ] 确认了源文件能不能动（默认只写副本）。
- [ ] 搜过正文里的旧书写约定（「公式一律写成纯文本」之类）。

改造后：

- [ ] 逐条看过对照报告，**需复核的条目逐条处理**（改写或确认不改）。
- [ ] `formula_norm.py validate` 跑过，缺 typst 的项如实标了 `skipped`。
- [ ] 渲染产物里**字面量残留数 = 0**（`$$` / `\frac` / `\_` 等）。
- [ ] PDF / DOCX / PPTX 的公式**用眼睛看过一遍**（分式有没有分数线、上下标位置对不对）。
- [ ] PPTX：注入后**用 PowerPoint 真开过**，没提示修复，形状数没变。
- [ ] 规范化的产物再规范化一次**一字不改**（幂等）。
- [ ] 验收判据用的是 `find_spans` 而不是 `scan`。

## 方法论依据

- **根因在源就不在渲染器**：渲染器只能处理已经写对的源。源里没有 LaTeX 时，
  换渲染器、换公式库都是白费功夫 —— 先判定「问题在源还是在渲染器」，
  再决定动哪里。
- **误报成本高于漏报**：把 `course_code` 改成 `course_{code}` 会**永久毁掉字段名**，
  而这种错误不会被任何"公式残留"判据发现（因为它是合法 LaTeX）。
  ⇒ 规范化只对**有上下文判定的命中**动手，宁可漏改，不可乱改。
- **表示层变换不改事实**：把伪公式改写成等价 LaTeX 是**表示层**变换 ——
  事实、结论、措辞一个都不动。⇒ 可以在派生链路上自动执行，
  而不必担心"AI 借改公式夹带私货"。
- **幂等是可验证的硬要求**：派生产物会被反复重算；
  规范化跑两遍必须一字不改，否则「讲义讲稿 ≠ 课件讲稿」这类同源判据会凭空变红。
- **单一真相原则**：全仓只有一份公式 —— 它在**源层**规范化一次，
  各载体（Markdown / PPTX / DOCX）只负责**渲染**自己的那一份，
  不各自再改一遍。
- **可证伪的验收**：「排版看着没问题」不是验收；
  「渲染产物里字面量残留 = 0」+「PowerPoint 真开过、形状数没变」+「闸跑绿」才是。
  同理，`validate` 的 `ok: true` 只证明管线跑得通，不证明公式对。
- **代价要写在交付说明里**：LaTeX 源在 PDF 里不再是可复制的纯文本
  （分式会变成排版结构）。这是**有代价的改进**，不说明就是隐瞒。

## Windows 平台说明

本 skill 的全部脚本用 `python` 或 `py` 调用，命令在 PowerShell 里执行：

```powershell
# 用 python（Windows 上更常见）
python scripts\formula_norm.py scan 讲义.md

# 或用 py 启动器
py scripts\formula_norm.py scan 讲义.md
```

注意这几点：

- 脚本路径用相对路径或反斜杠均可，PowerShell 里建议加引号包住含空格的路径。
  工作目录不在 skill 目录时用绝对路径：`<skill-dir>\scripts\formula_norm.py`。
- 读写文本文件显式带 `-Encoding UTF8`（`Get-Content`/`Set-Content`），
  否则中文在 PS 5.1 下会按 ANSI/GBK 解释而乱码。
- 读 `.ps1` 脚本时同样按 ANSI/GBK 处理，所以脚本内容尽量保持 ASCII，
  中文路径通过环境变量传进去。
- 删临时产物优先用**可恢复**的删除（能进回收站/可还原）；
  不可恢复的 `Remove-Item -Force` 只在明确知道自己在删什么时用。
- `scripts\` 下被 import 后会生成 `__pycache__\`。
  它不该留在 skill 目录里（skill 只放 LLM 执行需要的文件），交付前删掉。
- 本 skill 不依赖 `python3`、`bash`、`/tmp`；Windows 上不需要额外的 shell 适配。

### 跨平台说明

脚本本身是跨平台的 Python，Windows / macOS / Linux 都能跑。差异只在两处：

- **typst / pandoc 的查找**：先找 PATH，再看环境变量 `TYPST`（typst），
  再找常见安装位置。找不到时 `validate` 会如实标 `skipped`——
  **这不是失败，是没验证**，退出码为 2（区别于「跑过但失败」的 1）。
- **shell 语法**：本节给的是 PowerShell 写法；macOS / Linux 用等价的
  `python3 scripts/formula_norm.py scan 讲义.md` 即可，脚本无需改动。
