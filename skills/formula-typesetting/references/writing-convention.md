# LaTeX 公式书写规范

> 适用：AI 生成的讲义、教案、课件、报告。
> 目标：**源头就把公式写对**，下游不需要再"修公式"。
> 配套脚本：`scripts/formula_norm.py`（检测 + 建议）、`scripts/pptx_omml_inject.py`（PPTX 注入）。

---

## 1. 为什么规范的核心只有一条

AI 写公式时默认写「Unicode 伪公式」，因为它**看起来像**：

| AI 实际写出来的 | 渲染后的问题 |
|---|---|
| `e^(−γt)` | 脱字符冒充上标，γ 和 t 挤在一起 |
| `ω_d` | 下划线裸露，不是下标 |
| `ε/R` | 斜杠，不是分式 |
| `√(k/m)` | 根号只盖住一半 |
| `m·ẍ` | 中点当乘号，ẍ 的重音位置不对 |
| `xₙ₊₁` | Unicode 下标，字体缺字形就变豆腐块 |

实测一条真实生成链路（讲义 + 课件 + 构建脚本）grep `latex|katex|mathml|omml` **零命中**，
评测报告自己也写着「源文件没有任何公式」。

⇒ **问题不在渲染器，在源**。换渲染器没用，改源才有用。

规范因此只有一条核心要求：**公式用 LaTeX 源码写，排版交给管线。**

---

## 2. 三种载体，三种写法

| 载体 | 行内公式 | 独立公式 | 最终形态 |
|---|---|---|---|
| Markdown（讲义/教案/报告） | `$...$` | `$$...$$` | PDF 里是真分式/真上下标；DOCX 里是原生可编辑公式 |
| PPTX | 直接注入 OMML | 同左 | PowerPoint 原生公式（双击进编辑器，不是图片） |
| DOCX | 同 Markdown | 同 Markdown | Word 原生 OMML 公式 |

Markdown 里**不要**把公式放进 ` ``` ` 代码块——围栏里的 `$...$` 不会被排版。

## 3. 硬规则对照表

### 3.1 分式

| ✗ 别写 | ✓ 要写 | 说明 |
|---|---|---|
| `ε/R` | `\frac{\varepsilon}{R}` | 分式必须用 `\frac{分子}{分母}` |
| `c/(2m)` | `\frac{c}{2m}` | 分母带括号时**去掉**括号，`\frac` 自带分组 |
| `B²L²/R` | `\frac{B^{2}L^{2}}{R}` | 分子里可以有多个因子 |
| `√(k/m)` | `\sqrt{\frac{k}{m}}` | 🔴 根号里的分式要写 `\frac`，否则根号只盖住 `k` |

量纲不是分式：`rad/s`、`N·s/m`、`m/s` **保持纯文本**。

🔴 **阈值也不是公式**：「比较符 + 数字(+单位)」是条件，不是数学表达式。
`≥2 min`（至少 2 分钟）、`≤ 30 s`、`≥ 25 °C` **保持纯文本**。
写成 `$\geq 2 \min$` 有两个问题：`\min` 是 LaTeX 的**最小值算子**，
而这里说的是**单位「分钟」**；而且它和上面「量纲保持纯文本」自相矛盾
（`5 s` 不转、`≥2 min` 转，只因为前面多了个 `≥`）。
**例外**：单位词里出现希腊字母或下标时仍是公式（`≥2π`）。

🔴 **单位词不是算子**：`min`（分钟）、`sec`（秒）、`max` 这些名字**兼作普通词**。
`2 min` 要写 `2\,\mathrm{min}` 或纯文本，**不要**写 `\min`。

### 3.2 上下标

| ✗ 别写 | ✓ 要写 |
|---|---|
| `ω_d` | `\omega_{d}` |
| `A₀` | `A_{0}` |
| `xₙ₊₁` | `x_{n+1}`（连续的 Unicode 下标合并成一个组） |
| `e^(−γt)` | `e^{-\gamma t}` |
| `ω₀²` | `\omega_{0}^{2}` |

### 3.3 变音符

| ✗ 别写 | ✓ 要写 |
|---|---|
| `ẍ` | `\ddot{x}` |
| `ẋ` | `\dot{x}` |
| `θ̂` | `\hat{\theta}` |

### 3.4 乘号与运算符

| ✗ 别写 | ✓ 要写 | 说明 |
|---|---|---|
| `m·ẍ` | `m \cdot \ddot{x}` | 中点两侧要有"原子"才当乘号 |
| `×` | `\times` | 只在两个量之间用 |
| `⟹` | `\Longrightarrow` | |
| `∝` | `\propto` | |
| `−`(U+2212) | `-` | LaTeX 用普通减号 |

单个 `·` 不成公式：`带 · 的是乘号` 这种句子里的 `·` 保持原样。

### 3.5 函数名

| ✗ 别写 | ✓ 要写 |
|---|---|
| `ln(x)` | `\ln(x)` |
| `cos(ω_d t + φ)` | `\cos(\omega_d t + \varphi)` |
| `argmin Σ [...]` | `\operatorname{argmin} \sum [...]` |

函数名后面**不要**跟字母，否则会被劈坏（`\varepsilon` 不能变成 `\varepsilo n`）。

### 3.6 希腊字母

用命令写，不用 Unicode：`\varepsilon`（不是 `ε`）、`\omega`、`\gamma`、`\theta`、
`\mu`、`\zeta`、`\Lambda`、`\varphi`。

🔴 数学花体（`𝐵`、`𝜀`）只有 **Cambria Math** 有字形，其它字体会变豆腐块。
不要手工打 Unicode 花体，让排版引擎生成。

## 4. 三种典型场景的标准写法

**① 独立成行的公式**（Markdown）

```
$$
\gamma = \frac{c}{2m} = \frac{N^{2}\mu^{2}L^{2}}{2m R}
$$
```

**② 夹在中文句子里的公式**（Markdown）

```
这里的 $\varepsilon$ 是感应电动势，阻尼系数 $c = \frac{B^{2}L^{2}}{R}$ 是常数。
```

**③ 幻灯片上的公式**（PPTX）

- 整条 bullet 是公式 → 整条替换成 OMML；
- bullet 是"文字 + 公式" → 文字留 run，公式用 `<a14:m>`；
- bullet 是"文字 + 公式 + 文字" → 拆成 `文字 run` + `<a14:m>` + `文字 run`。

## 5. 给 AI 的约定片段（可直接粘贴）

> **公式书写要求**（写讲义/教案/课件时必须遵守）：
> 1. 所有数学公式用 LaTeX 源码写，行内用 `$...$`，独立成行用 `$$...$$`；
> 2. 不要用 Unicode 伪公式：禁止 `ε`、`ω_d`、`A₀`、`e^(−γt)`、`√(k/m)`、`m·ẍ`；
> 3. 分式一律 `\frac{}{}`，根号里的分式写 `\sqrt{\frac{}{}}`；
> 4. 上下标一律 `_{}` / `^{}`，希腊字母用命令（`\varepsilon`、`\omega`）；
> 5. 乘号用 `\cdot`，函数名用 `\ln` `\cos` `\sin`，极小/极大用 `\operatorname{argmin}` / `\operatorname{argmax}`；
> 6. **量纲保持纯文本**（`rad/s`、`N·s/m`、`s⁻¹`），不要改写成公式；
> 7. **阈值保持纯文本**（`≥2 min`、`≤ 30 s`）；单位词 `min`/`sec` 是**分钟/秒**，不是 `\min`/`\sec`；
> 8. 公式**不要**放进代码块（```），围栏里的 `$...$` 不会被排版；
> 9. 中文正文里出现的变量也要包成行内公式：`这里的 $v$`；
> 10. 不要在公式里夹中文常量，确需说明就放在公式外的文字里。

## 6. 自检清单（提交前 30 秒过一遍）

- [ ] 有没有 Unicode 希腊字母？
- [ ] 有没有 `^(`、`_x`、`²`、`₀`？
- [ ] 有没有 `√(` 后面跟 `/`？
- [ ] 有没有 `·` 旁边是中文？
- [ ] 分母带括号的分式，括号去掉了吗？
- [ ] 量纲有没有被误改成公式？
- [ ] 阈值有没有被误改成公式？（`≥2 min` 里 `min` 是**分钟**，不是 `\min`）
- [ ] 有没有把「A/B 类」当成「A 除以 B」？
- [ ] 公式是不是被关在代码块里？
- [ ] 正文里"公式写成纯文本"这类**旧约定**还在吗？（改成新约定）

自动化：

```powershell
python scripts\formula_norm.py scan  讲义.md                                    # 只报告
python scripts\formula_norm.py fix   讲义.md --out 讲义_规范化.md --report 对照.md   # 出副本 + 逐条对照
python scripts\formula_norm.py selftest                                          # 回归自测
python scripts\formula_norm.py validate 讲义_规范化.md                            # 实测能不能落地
```

`fix` 的产物永远是**副本**；报告里带「需复核」的条目必须逐条看过再采纳。

🔴 **`validate` 只验管线，不验内容。** 它跑通 pandoc/typst/docx 就报 `ok: true`，
但一份把公式整段吃掉的坏文档同样能通过。改完必须再查一次**字面量残留**
（渲染产物里出现 `$$`、`\frac`、`\theta`、`\_` 就是没被识别），
最好把 PDF 转成 PNG 用眼睛看一遍。

## 6b. 文档里已有一部分 LaTeX 时

半成品文档很常见：一部分公式已经是 LaTeX，另一部分还是 Unicode 伪公式。
改造时**已有围栏的内容只做规范化，不再套第二层分隔符**。

三条曾经踩过的坑（脚本已修并设了文档级回归，但改脚本后要跑 `selftest` 确认）：

| 坑 | 现象 | 根因 |
|---|---|---|
| 已有 `$$` 被二次包裹 | 嵌套 display math ⇒ 渲染时整段公式消失 | 围栏外又加了一层 |
| 已有 `$...$` 写成 `$$...$$` | pandoc 判为字面文本 ⇒ PDF 里出现 `$$` | 分隔符被裁剪后又补了一个 |
| 代码块围栏被吞 | 代码块变正文 ⇒ 变量名的 `_`、`*` 被转义 | 开闭围栏没有写回输出 |

围栏内的**多行结构**（`\begin{pmatrix}`、`\begin{aligned}`）会原样保留，
不做内部改写——这类结构里的下标不会被补成 `_{...}`，需要自己检查。

## 7. 与「公式一律写成纯文本」的旧约定冲突

旧讲义的《使用说明》里写着"公式一律写成纯文本，可直接复制进 Word 或报告"。
改成 LaTeX 后这句话就**过时了**，必须同步改掉，否则读者（和后续的 AI）会按旧约定继续写伪公式。

`formula_norm.py` 会自动检出这类冲突并给出建议措辞：

```
⚠ 书写约定冲突（改完公式后必须同步改这几行）
| 9 | 「公式一律写成纯文本」 | > 3. 本讲义的公式一律写成纯文本… |

建议统一改成：
> 公式一律用 LaTeX 写（行内 `$...$`、独立成行 `$$...$$`），由排版管线渲染成真正的公式；
> 乘号写作 `\cdot`，分式写作 `\frac{}{}`。
```

**代价要说清楚**：LaTeX 源在 PDF 里**不再是可复制的纯文本**（分式会变成排版结构）。
需要纯文本的场景，从 `.md` 源或 DOCX 取，不要从 PDF 复制。
