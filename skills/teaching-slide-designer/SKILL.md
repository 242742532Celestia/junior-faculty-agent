# 教学幻灯片设计器

## 这个技能解决什么

教师做课件最常见的失败不是"不会做"，而是**把教案抄成了幻灯片**：一页塞九条要点、页标题写成"其他"、讲稿一个字没有、图表贴上去不标来源。这样的 PPTX 技术上合格，作为教学材料是废的。而这些问题**肉眼难发现、评审也难说清**——"这页字太多了"是感受，"要点超过六条、单条超过三十字、正文没有讲稿备注"是判据：前者吵不出结果，后者可以自动判定。

本技能给出从教学目标到可放映 PPTX 的**可执行流水线**，并自带两件工具：build_pptx.py（纯标准库 PPTX 生成器，产出带讲授者备注的可编辑 pptx）与 slide_spec_lint.py（教学规范审查器，输出可脚本化消费的检查项编号）。核心主张只有一句：**一页一个认知任务，标题是一句可判真假的话，讲解进讲稿，事实带来源。**

## 什么时候用

用：

- 已有教案或讲稿，要转成能投影放映的课件时；
- 已有 PPT，但拿不准"是不是太满""标题有没有信息量""图要不要标来源"时；
- 给学习平台准备可下载课件（要求可编辑、上传不跑版）时；
- 做微课、翻转课堂等短时高密度课件，需严格控页数时；
- 教研室互审课件，需要一套**共同判据**而不是个人口味时。

**不用**：只需要海报或单张图时；只需要纯文字讲稿时；做的是**研究成果汇报**（从论文重构叙事）时；需要实时互动与动画演示时。

## 输入

**必填**（缺项时先按默认起草并标为待核验假设）：本节课的**认知目标**（学完能做什么、能说出什么）；时长与页数预算；受众（年级、专业背景、是否跨专业）；素材（要点、图表、公式、案例）。

**选填**（**没给就留空，不编**）：授课设备（投影 / 智慧黑板 / 机房 / 板书为主）；交付形态（只放映 / 发学习平台 / 存档送审）；已有课件文件；数据来源清单与可公开范围。

**不编造原则**：本技能不生成事实性内容。标题、要点、数据、来源必须来自输入素材或教师本人确认；宁可留空白页让人补，也不要替教师杜撰一个"研究表明"。

## 执行步骤

### 第 1 步：锁定这一页要解决的认知任务

不写"讲什么知识点"，要写"**看完这页学生应该能做什么 / 说出什么**"。一个认知任务对应一页，一页解决不了两个任务就拆页。「讲误差传播」不合格，「让学生能判断一次测量中哪些环节引入了误差」合格。写不出合格版本，说明这页的教学目标本身没定，先回去定目标。

### 第 2 步：判定该页属于哪种版式

脚本只支持 7 种版式。选错版式是最常见的浪费——把对照内容塞进一页长列表、把需要看的图做成纯文字页。

**表 1 · 七个版式的选择判据**

| 版式 | 什么时候用 | 不要用它的信号 |
|---|---|---|
| **title** | 整节课的开场，**全文唯一且必须在第 1 页** | 想再放一个扉页 |
| **bullets** | 一组并列要点（不超过 6 条），以文字为主 | 要点超 6 条却不想拆页 |
| **two-column** | 两组内容需**同页对照**，每组不超过 3 条 | 两组之间无对照关系，只是凑版面 |
| **image-focus** | 一张图/表/公式是本页唯一信息主体 | 图只是装饰，正文才是重点 |
| **quote** | 把一句权威表述立起来做锚点 | 引一句自己写的话 |
| **section** | 分节、换章、转场，交代"现在讲到哪" | 想用它做第二个封面 |
| **blank** | 现场手写、板书、演算，放映时需要留白 | 还没想好这页要干什么时 |

### 第 3 步：写断言式标题

页标题不是**主题词**，是**这一页的结论**。断言式标题（assertive title）是可判真假的陈述句：「其他」不合格，「三种数据来源里只有一种能追溯到原始记录」合格；「实验步骤」不合格，「每一步都保持低温，直到 pH 回到中性」合格。

lint 的 L11 只对纯分类词（其他、概况、总结、要点、背景、方法等）给出 INFO，**加了限定语的分类词它抓不到**，断言性主要靠你自己把关。自检法：把标题念出来，若像"这一节讲……"就重写。

### 第 4 步：切分要点

每条要点是**一个完整命题**（主谓宾齐全、可独立成立），不是一个词组。

**表 2 · 长句拆分前后对照**

| 写法 | 问题 | 拆后 |
|---|---|---|
| 细胞膜主要由磷脂双分子层构成，其中还镶嵌着各种蛋白质，负责物质运输、信息传递等功能 | 一条塞了三个命题 | ① 骨架是磷脂双分子层<br>② 镶嵌的蛋白质承担物质运输<br>③ 同一批蛋白质还参与信号传递 |

要点数上限 6 条（L01，超了是 ERROR），单条上限 30 字（L02，WARN），一页正文合计上限 120 字（L04）。**触线就往讲稿里搬，不要缩字号。**

### 第 5 步：把讲解移进讲稿

幻灯片给**观众**看，讲稿给**讲授者**用，两者职责分离是本技能的核心机制。

**表 3 · 内容该放哪儿**

| 内容类型 | 幻灯片正文 | 讲稿备注字段 |
|---|---|---|
| 核心命题 | 写（断言式标题 + 要点） | 不重复，只写"为什么这样讲" |
| 举例、类比、故事 | 不写 | 写（口述独有的价值） |
| 推导过程、计算步骤 | 不写 | 写 |
| 过渡句、提问 | 不写 | 写 |
| 数据与图表 | 写结论句 + 标来源 | 写口径、读图顺序、常见误读 |
| 易错点与边界条件 | 不写 | 写 |

讲稿长度控制在 10–800 字（L12）：少于 10 字是 WARN，说明撑不住这一页；多于 800 字是 INFO，说明该拆页。

### 第 6 步：标来源

凡出现外部事实、数据、统计量、引文的页面，footer 字段必须有来源，否则触发 L08（WARN）。自绘示意图写"来源：示意图为作者自绘"；引用他人数据写"来源：作者，年份，出处名称或链接"；改绘他人图表写"来源：改绘自作者，年份，图表出处"；教材内容写"来源：教材第 X 章"，不确定就只写教材名。

**事实性内容不得编造**：作者、年份、页码不确定就留空待补，或换成不依赖具体出处的表述。绝不生成看起来很真的假引用。

### 第 7 步：生成 PPTX

在工作目录下（规格 JSON 与图片的相对位置以该目录为基准）：

```powershell
python scripts/build_pptx.py spec.json -o slides.pptx --check
```

--check 做 OOXML 结构自检：部件齐全、XML 可解析、关系引用闭合、页序对应、备注挂载。退出码 0 成功、1 规格错误、2 结构自检失败。规格 JSON 字段结构见表 5。

版面固定 16:9。字号由脚本固定：页标题 40pt、正文 24pt、二级要点 20pt、脚注 12pt。**正文与要点不得低于 18pt**；12pt 只用于来源这类附属信息。

### 第 8 步：过 lint

```powershell
python scripts/slide_spec_lint.py spec.json
python scripts/slide_spec_lint.py spec.json --json
```

**表 4 · 检查项与处置原则**

| 编号 | 级别 | 判什么 → 怎么处置 |
|---|---|---|
| L01 | ERROR | 要点超 6 条 → 拆页，次要条目移进讲稿 |
| L02 | WARN | 单条超 30 字 → 拆成短句，长解释进讲稿 |
| L03 | WARN | 标题超 20 字 → 压成一句短断言 |
| L04 | ERROR | 正文页没有讲稿备注 → 补讲稿，不能带过 |
| L04 | WARN | 正文合计超 120 字 → 拆页 |
| L05 | ERROR | 正文页没有标题 → 补断言式标题 |
| L06 | WARN | 出现"如上图/如下图/如前所述" → 改成"这张图里""上一页的结论是" |
| L07 | ERROR | 封面多次出现或不在第 1 页 → 封面留一个，分节用 section 版式 |
| L08 | WARN | 事实/数据类表述没有来源 → 补 footer 字段 |
| L09 | WARN | 既没要点也没图 → 补内容，或改 blank / section 版式 |
| L10 | WARN | 有图且要点超 4 条 → 减少要点，图会分走注意力 |
| L10 | INFO | 有图但没有图注 → 补 caption 字段 |
| L11 | INFO | 标题是分类词不是断言 → 改成断言句 |
| L12 | WARN / INFO | 讲稿过短 / 过长 → 补讲稿 / 拆页 |
| L13 | — | 编号保留，本仓库暂未启用 → 忽略 |
| L14 | ERROR | 占位符残留（待补/待定/TBD/XXX 等）→ 补齐或删除再交付 |
| L15 | ERROR | 文字超出所在文本框 → 缩短文字或降字号（PowerPoint 会自动缩字，字号会小于设计值） |

**处置原则**：ERROR 必须清零，不存在"先交再说"。WARN 逐条判断，依据是"这一页教学上成立吗"，不是"工具报了就改"。阈值可用 --thresholds 覆盖（脚本里的 THRESHOLDS 字典），但**改动阈值要写进交付说明**，否则评审无法判断口径。

### 第 9 步：人眼过一遍

自动检查查不出版面问题。生成后必须打开放映一遍：文字有没有溢出或压住分隔线；有没有字小到后排看不清（正文不低于 18pt）；图有没有压住文字、图例有没有被裁掉；实际讲完是否落在课时预算内；有没有哪一页不看幻灯片讲不下去（讲稿没写够），或离开你就讲不下去（内容全写在幻灯片上）。

## 版式原型表与文字高度表（几何的单一事实源）

七种版式的几何**不是**散在渲染代码里的坐标，而是写在
`scripts/slide_layouts.py` 里的**版式原型表**。渲染器与判据**共用这一份**。

| 槽位组 | 画布 | 内容区 | 两栏 | 图片 | 页脚 |
|---|---|---|---|---|---|
| 尺寸（pt） | 960 × 540 | 宽 852 / 高 360 | 栏宽 411 / 栏距 30 | 图宽 732 / 左右各留 60 | 高 20 |

**为什么值得单列一张表**

1. **判据能读到几何** —— "这页字放得下吗"可以机器算，不用人眼在 PowerPoint 里看。
2. **几何是数据** —— 改一个版式的坐标改一行表，不是翻代码。
3. **不会漂移** —— 渲染器按它画、判据按它量，两边共用同一份 ⇒ 判据说的和画出来的是同一件事。
   （两份几何各算一套 ⇒ 判据会与渲染器漂移，那种判据没有价值。）

**文字高度表**（行高 = 字号 × 1.35；本仓库的文本框内边距为 0）

| 字号 | 1 行 | 2 行 | 3 行 | 4 行 | 5 行 |
|---|---|---|---|---|---|
| 12pt（页脚） | 17 | 33 | 49 | 65 | 81 |
| 14pt（图注） | 19 | 38 | 57 | 76 | 95 |
| 20pt（二级要点） | 27 | 54 | 81 | 108 | 135 |
| 24pt（正文） | 33 | 65 | 98 | 130 | 162 |
| 28pt（引文） | 38 | 76 | 114 | 152 | 189 |
| 40pt（正文页标题） | 54 | 108 | 162 | 216 | 270 |
| 44pt（封面/章节标题） | 60 | 119 | 179 | 238 | 297 |

> 表里每一格 = `ceil(字号 × 1.35 × 行数)`。自检会**逐格核对**这个公式，
> 不是只查"行数越多越高"—— 某一档凭感觉多写 1–5 pt 是手写这种表最常见的错，
> 那样会让溢出判据偏松、该报的报不出来。

**溢出怎么判**：一行能放多少字按 **em** 算（全角 1.0、半角 0.5），
`行宽容量 = (框宽 − 缩进) ÷ 字号`；段落行数 = ⌈文本宽度 ÷ 容量⌉；
所需高度 = 查表 + 段前距。**所需高度 > 框高 ⇒ 装不下**。

🔴 **装不下 ≠ 看得见**：PowerPoint 的文本框带 `normAutofit`，
文字超出框高时**不会露出来**，而是**自动缩小字号** ——
于是"设计的 24pt"实际变成 18pt，而版面看起来还是正常的。
这是**静默失效**，所以有 L15 判据把它逼出来（字数规则 L03/L04 抓不到它：
21 字的封面标题字数合规，但 44pt 下根本放不进 852pt 的框）。

## 中国高校语境要点

- **学时与页数配比**：经验值是每 45 分钟授课约 10–15 页（含封面与分节页），"新内容页"不超过一半，其余留给提问、演示与练习。以各校校历与班型为准。
- **大班 vs 小班**：合班百人以上的大班，每 45 分钟新内容页控制在 6–8 页，多留提问与演示；研讨课可一页一个论点，但要更频繁停下来做口头检查。
- **投影 vs 智慧黑板**：智慧黑板可延展，适合现场手写推导，此时关键步骤应**留白**而非预先写满；投影条件下正文少字、字号偏大。
- **机房与实验课**：机房课页面以"操作步骤 + 预期现象 + 出错排查"三段为主；实验课的数据与误差分析至少占一页，否则学生复盘没有锚点。
- **混编班差异**：专业跨度大的班级，同页术语必须中英并列；跨专业例子不能默认共享背景，讲稿里补一句"为什么这个例子对你们也成立"。
- **课件要发到学习平台**：交付物**必须**含可编辑源（规格 JSON 或 PPTX 本体）与可编辑文本，不要只交 PDF；上传版本要保留页内标题结构，便于课后检索。需存档的再留一份 spec JSON 并记下生成命令与阈值设置。
- **讲稿与课程思政**：讲稿是课程思政案例的天然落点——案例写在讲稿里、正文只留结论句，既不挤占版面，又能在提问环节自然引出。**不要**把思政语录做成单独一页大字海报占掉黄金时间。

## 易错点

- ❌ 把教案抄成幻灯片 → ✅ 一页只承担一个认知任务；举例、推导、过渡全部进讲稿。
- ❌ 要点当句子写（词组拼贴） → ✅ 每条要点是主谓宾齐全、可独立成立的命题。
- ❌ 页标题写成"其他""总结""背景" → ✅ 标题写成可判真假的断言句；加了限定语的分类词要靠自己改。
- ❌ 讲稿写进正文 → ✅ 正文只留结论与要点；讲稿进备注字段，放映时在备注视图可见。
- ❌ 出现"如上图""如前所述" → ✅ 幻灯片是并置版面，线性指代在观众眼里不成立；改成"这张图里""上一页的结论是"。
- ❌ 有数据有引文却没标来源 → ✅ 事实性页面一律补来源字段；出处不确定宁可留空待补，也不编一个像真的引用。
- ❌ 把 PPTX 当唯一交付物 → ✅ 同时交付 spec JSON 与可编辑源；平台上传、后续重生成、换图都靠它。
- ❌ 用图片承载必须口述的信息 → ✅ 图上只放必须被"看"的信息；必须被"听"的写进讲稿，不要截文字冒充讲解。
- ❌ 正文与要点字号低于 18pt → ✅ 正文 24pt、二级要点 20pt 是底线；12pt 只用于来源这类附属信息。
- ❌ 每页都塞满 6 条以上 → ✅ 六条是上限不是目标；超过 4 条就该怀疑这页承担了两个任务。
- ❌ 封面做成多页 → ✅ title 版式全文只出现一次且在第 1 页，章节过渡一律用 section 版式。
- ❌ 把 lint 的 WARN 当成可以忽略 → ✅ ERROR 必须清零；WARN 逐条写处置与理由，理由就是"这页教学上成立"。
- ❌ 只按字数估页容不装得下 → ✅ 用几何判（L15）：字号 × 框宽决定一行能放多少，标题框只有 60pt 高，超了就自动缩字。

## 方法论依据

- **认知负荷理论（Sweller 的认知负荷理论）**：工作记忆容量有限，一页同时呈现的要素越多，外在负荷越高。据此设定要点数、单条字数与正文总字数上限——这些阈值是教学经验值，不是普适定律。
- **Mayer 的多媒体学习原则**：信号词原则、冗余原则、空间邻近原则。据此规定"标题即结论"、并置版面不用线性指代、图表与结论句同页相邻。
- **并置媒介的指代失效**：幻灯片属于并置媒介，观众看到的是整页而不是一条线性序列；"如上图所示"在纸面上成立、在并置版面里失效，因此改为显式指认本页元素。
- **幻灯片与讲稿的职责分离**：幻灯片是观众的视觉通道，讲稿是讲授者的言语通道。据此把举例、推导、过渡、易错点移入讲稿，正文只保留可被视觉快速扫描的结论与要点。
