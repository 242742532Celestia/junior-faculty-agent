# 高校语境适配（K-12 → 中国高校）

完整映射表见 `references/he-context-adapter.md`（**本技能的权威来源**）。
本文件是给 Agent 快速查的速查版 + 判断规则。

## 为什么需要这个

上游教学技能（`GarethManning/education-agent-skills`，MIT）以**英式 K-12** 为默认语境：
学段是 Year 1–13，课时 50 分钟，评价用 UK National Curriculum + GCSE/A-Level + Key Stage。

中国高校**没有**这些制度。直接产出给中国教师，交付物会带着明显错位：
「Year 9 生物课自然选择单元」「KS3 达标目标」「formative assessment（UK 体系）」。

**适配不是翻译，是制度替换。**

## 三条执行规则

1. **先映射再执行** —— 输入里的 `Year N` / `KS3` / `secondary school` 一律先换成高校口径，
   再往下做设计。**不要在输出里保留英式学段表述。**
2. **中文产出，术语中英并列** —— 正文中文；专业术语首次出现时并列
   （形成性评价 / formative assessment）。术语表本身不用翻译。
3. **中国维度要补** —— 课程思政、毕业要求支撑、教材 ISBN、考核百分比构成、
   教学工作量折算，上游完全没有。产出时按下方清单补齐，并标注为高校语境补充项。

## 课程目标—毕业要求—核心素养映射

本节处理一条高校教师最常被追问、却最容易被答错的链条：**这门课的课程目标凭什么支撑了毕业要求，对应的核心素养维度又是什么**。上游技能完全没有这一层，必须主动补。

### 三列映射表

| 课程目标（可观察动词） | 毕业要求指标点（院系给定，没给留空） | 核心素养维度 | 支撑形式（哪次课 / 哪份作业） |
|---|---|---|---|
| 能够……（可观察动词） | | 学校自定口径，待学院确认 | 第 X 周第 Y 次课 + 第 Z 次作业 |
| | | | |

### 关键事实澄清（先读这段，再填表）

- 中国**普通本科院校**没有 K-12 那种法定统一的"核心素养"框架。**不得**套用或编造 K-12 课标的素养维度名称与条款号。
- 高校里对应的东西通常是学校 / 学院自定的表述：**专业核心能力、课程育人目标、学科核心素养、一课程一目标、毕业要求支撑矩阵**。
- 因此本技能的做法是：**三列映射里第三列（核心素养维度）标注为「学校自定口径，待学院确认」**，并**留空**，由学院填写；本技能**不替院系定义指标点体系**。
- 如果用户所在院校确实有校级核心素养清单，**以校级清单为准**，把清单原文的维度名称与编号填进去——**但编号必须由用户提供，不得推测**。

**禁止项**：

- 不得编造"毕业要求 3.2""核心素养 5 项"这类编号。
- 不得把 K-12 的"文化基础 / 语言运用 / 思维发展 / 自主合作"等名称直接当作高校课程目标的素养维度。

### 常见维度（仅作占位参照，需按学校口径替换）

批判性思维 / 创新意识 / 工程伦理与社会责任 / 团队协作与沟通 / 终身学习与自我管理 / 跨学科整合 / 国际视野 / 数据素养与定量推理。

> 以上为常见维度举例，**不是**任何学校的官方清单；正式映射须以本校 / 本学院文件为准。该栏只作待填占位，实际填写以学院给出的维度名称为准。

### 支撑形式列怎么填

- 每条目标至少一个落点（哪一周、哪份作业、哪次考核）；落点写不出来，说明这条目标没有活动在支撑它。
- **落点为空的行 = 目标悬空，必须处理**：要么调目标（改成能被现有活动支撑的动词），要么调任务（补一个能产生该证据的作业或考核）。
- 支撑形式必须是**可核对的作品或行为**（一份报告、一次答辩、一份数据处理记录），不能写"通过课堂讨论达成"。

### 与毕业要求支撑矩阵的关系（避免重复劳动）

- `curriculum-crosswalk` 负责**课程—毕业要求交叉表**（这门课在专业课程体系中的位置）。
- `backwards-design-unit-planner` 负责**目标—证据—活动的倒推**（单元层面怎么设计）。
- 本节负责**单门课程内部**的三列对照与落点核对。
- 三者共用同一套指标点编号，**编号只有一个来源**（院系给定），不要各自另编一套。

## 中国高校特有维度（必须主动补）

| 维度 | 要求 |
|---|---|
| **课程思政融入** | 每章至少 1 个融入点，写明融入方式（案例/问题导入/价值讨论/学科史脉络）。**判据：拿掉那句话后课程内容会缺一块**——否则是硬贴标签 |
| **毕业要求支撑** | 每个课程目标对应到具体毕业要求指标点。指标点**未由用户提供时整表标「待补充」**，不编号 |
| **考核方式构成** | 平时/期末占比必须给出且**合计 100%** |
| **教材与参考书** | ISBN 或可核实的书目信息。**查不到不编**，标「待补充」 |
| **实验/实践环节** | 注明学时数、分组方式、考核占比 |
| **工作量折算** | 学时与工作量的对应关系（用户需要时） |

**本节补充的院内口径**：

- 毕业要求指标点编号**由院系给定**，用户没给就留空并标「待补充」，不自行编写。
- 专业核心能力 / 课程育人目标的**具体口径与条目数以学院文件为准**，本技能只转述不扩展。
- 跨专业、专升本、境外学生若用同一份映射表，要**另注明差异**（另附说明行，不改动主表）。
- 该映射表通常要**按学年更新**（培养方案修订会改指标点），映射表要标**版本与更新日期**。

## 禁止事项

- ❌ 把上游示例（如"自然选择单元"）当成用户的课程内容交付
- ❌ 把 K-12 的 band/tier 评分体系当成中国高校及格线
- ❌ 编造 ISBN / 学分号 / 毕业要求编号 / 参考文献 / 期刊分区 / 政策文件编号
- ❌ 输出英文界面词（formative/rubric）而不给中文对应
- ❌ 因为"不适用"就静默跳过——应明确告诉用户该技能不适用
- ❌ 把 K-12 的素养维度名称（如"文化基础 / 语言运用 / 思维发展 / 自主合作"）直接搬进高校课程目标 → ✅ 第三列标「学校自定口径，待学院确认」并留空，由学院填写
- ❌ 编造"毕业要求 3.2""核心素养 5 项"这类编号 → ✅ 编号只能来自院系文件，用户没给就写「待补充」
- ❌ 第三列自己填了内容却不说来源 → ✅ 每格内容都注明出处（校级清单 / 学院文件 / 待确认）
- ❌ 课程目标写了但映射表里没有支撑形式落点 → ✅ 每条目标至少一个落点；空行要么调目标要么调任务
- ❌ 映射表没有版本与更新日期 → ✅ 标版本号 + 更新日期，培养方案修订后同步更新
- ❌ 把本技能当成院系指标点体系的定义者 → ✅ 本技能只做对照与核对，指标点体系以学院文件为准

## 判断规则：何时该用本适配

| 情形 | 处理 |
|---|---|
| 教学技能输入含 `Year N` / `KS2` / `KS3` / `secondary school` | **必须**先查本表映射 |
| 教学技能要产出课时安排 | **必须**核对 45 分钟 / 2 学时口径 |
| 教学技能要产出考核方案 | **必须**换成形成性/终结性考核，并给百分比 |
| 教学技能要产出大纲 | **必须**补课程思政与毕业要求支撑 |
| 教学技能要产出课程目标 | **必须**补课程目标—毕业要求—核心素养映射（第三列留空待学院确认） |
| 教学技能要产出教材清单 | **必须**核实 ISBN，不得编 |
| 科研类技能 | 一般无需本适配（无 K-12 语境问题） |
| 技能输入含 Year 1–6 / EYFS | **停止**，说明超出高校教师职责范围 |
