# 教学课件生成器

## 这个技能解决什么

课件的失败有两类，**只有第二类会咬人**：

| 失败模式 | 表现 | 谁会发现 |
|---|---|---|
| 讲得不好 | 一页塞九条要点、标题写"其他"、讲稿一个字没有 | 教师自己，或同行评审 |
| **文件不对** | PowerPoint 打开直接 `HRESULT E_FAIL`；或能打开，但正文从设计的 12pt 被悄悄缩成 9pt | **没有任何人会主动发现** |

第二类是**静默失效**：版面看起来正常，放映时后排看不清；或者文件根本打不开，
而所有"关系引用闭合"式的自检**全绿**——因为这类错不在关系图里，在 **OOXML 契约**里。

本技能把这类错变成机械判据：

* `build_pptx.py` —— 纯标准库 PPTX 生成器（`json` / `zipfile`，零第三方依赖），
  产出带讲授者备注的可编辑 `.pptx`，并自带 **OOXML 契约自检**；
* `slide_layouts.py` —— **版式原型表 + 文字高度表**（几何的唯一真相）；
* `slide_spec_lint.py` —— 教学规范审查器，输出可脚本化消费的检查项编号。

核心主张一句话：**几何是数据不是代码；装不下要报出来而不是让它悄悄缩字；
生成完必须用 PowerPoint 真打开一次。**

> 教学侧的内容判断（哪一页该写什么、标题该断言什么）在本技能之外，
> 见 `teaching-slide-designer`。本技能只管**把确定的内容变成正确的文件**。

## 什么时候用

用：

- 已有逐页脚本/规格 JSON，要产出可放映、可编辑的 `.pptx` 时；
- 拿到一份"用别的工具生成的课件"，怀疑字号被缩、版面在换机器上跑版时；
- 需要给学习平台上传的课件（要求可编辑、上传不跑版）时；
- 批量重生成课件（改了一页，不想重排 30 页）时；
- 做**课件生成器本身**（自研、封装、或把生成能力随交付物一起分发）时。

**不用**：只需要海报或单张图时；只需要纯文字讲稿时；
做的是**研究成果汇报**（从论文重构叙事）时；需要实时互动与动画演示时。

## 输入

**必填**：一份**幻灯片规格 JSON**（`spec.json`）。字段契约见下方「输出模板」。

**选填**（没给就留空，不编）：图片素材（相对 `spec.json` 所在目录）；
授课设备与投影条件；页数预算。

**不编造原则**：本技能不生成事实性内容。标题、要点、数据、来源必须来自上游素材
或教师本人确认；宁可留空让人补，也不要替教师杜撰一个"研究表明"。

### 规格 JSON 的字段契约

| 字段 | 适用版式 | 类型 | 说明 |
|---|---|---|---|
| `meta.title` / `meta.author` / `meta.subject` | 全局 | str | 写进文档属性 |
| `slides[].layout` | 全局 | enum | `title` / `bullets` / `two-column` / `image-focus` / `quote` / `section` / `blank` |
| `slides[].id` | 全局 | str | 稳定页号（`P1`…）。**增量重生成靠它定位**；也决定这一页的强调色 |
| `slides[].title` | 全部 | str | 页标题 |
| `slides[].subtitle` | `title` / `section` / `quote` | str | 副标题 / 出处 / 眉题 |
| `slides[].bullets[]` | `bullets` / `two-column` / `image-focus` | str 或 `{text, level}` | 要点；`level` 0/1/2 |
| `slides[].notes` | 全部 | str | **讲授者备注**（讲稿）。`bullets` / `two-column` / `image-focus` 必填 |
| `slides[].footer` | 全部 | str | 来源标注（事实页必填） |
| `slides[].image` | `image-focus` | str | 图片路径，相对 `spec.json` 所在目录 |
| `slides[].caption` | `image-focus` | str | 图注 |

`level` 语义：`two-column` 里 **0 级要点进左栏，1 级及以上进右栏**；
右栏为空时按数量对半分。

## 执行步骤

### 第 1 步：选版式

| 版式 | 用它的信号 | 不要用它的信号 |
|---|---|---|
| `title` | 整节课开场，**全文唯一且必须在第 1 页** | 想再放一个扉页 |
| `bullets` | 一组并列要点（≤6 条），以文字为主 | 要点超 6 条却不想拆页 |
| `two-column` | 两组内容需**同页对照** | 两组之间无对照关系，只是凑版面 |
| `image-focus` | 一张图/表/公式是本页唯一信息主体 | 图只是装饰，正文才是重点 |
| `quote` | 把一句权威表述立起来做锚点 | 引一句自己写的话 |
| `section` | 分节、换章、转场 | 想用它做第二个封面 |
| `blank` | 现场手写、板书、演算 | 还没想好这页要干什么时 |

### 第 2 步：写规格 JSON

照「输出模板」的完整示例写。三个硬要求：

1. **每个正文页都要有 `notes`** —— 幻灯片给观众看，讲稿给讲授者用；
2. **讲稿只写在这个字段里**，不要另建一份讲稿文件（两份必然漂移）；
3. **事实/数据页要有 `footer`**。

### 第 3 步：生成

```powershell
python scripts/build_pptx.py spec.json -o slides.pptx --check
```

`--check` 做结构自检。退出码：`0` 成功 / `1` 规格错误 / `2` 结构自检失败。
不带 `--check` 时只生成不校验（**不推荐**：本技能的价值一半在这个自检里）。

自检覆盖：部件齐全、XML 可解析、关系引用闭合、页序与部件编号一一对应、
备注挂载双向闭合、**字号单位**、**段前距位置**、**content type 声明**。

### 第 4 步：过审查器

```powershell
python scripts/slide_spec_lint.py spec.json
python scripts/slide_spec_lint.py spec.json --json
```

**表 · 检查项与处置原则**

| 编号 | 级别 | 判什么 → 怎么处置 |
|---|---|---|
| L01 | ERROR | 要点超 6 条 → 拆页，次要条目移进讲稿 |
| L02 | WARN | 单条超 30 字 → 拆成短句，长解释进讲稿 |
| L03 | WARN | 标题超 20 字 → 压成一句短断言 |
| L04 | ERROR | 正文页没有讲稿备注 → 补讲稿，不能带过 |
| L04 | WARN | 正文合计超 120 字 → 拆页 |
| L05 | ERROR | 正文页没有标题 → 补断言式标题 |
| L06 | WARN | 出现"如上图/如下图/如前所述" → 改成"这张图里""上一页的结论是" |
| L07 | ERROR | 封面多次出现或不在第 1 页 → 封面留一个，分节用 `section` |
| L08 | WARN | 事实/数据类表述没有来源 → 补 `footer` |
| L09 | WARN | 既没要点也没图 → 补内容，或改 `blank` / `section` |
| L10 | WARN | 有图且要点超 4 条 → 减少要点，图会分走注意力 |
| L10 | INFO | 有图但没有图注 → 补 `caption` |
| L11 | INFO | 标题是分类词不是断言 → 改成断言句 |
| L12 | WARN / INFO | 讲稿过短 / 过长 → 补讲稿 / 拆页 |
| L13 | — | 编号保留，本仓库暂未启用 → 忽略 |
| L14 | ERROR | 占位符残留（待补/待定/TBD/XXX 等）→ 补齐或删除再交付 |
| L15 | ERROR | 文字超出所在文本框 → 缩短文字或降字号（PowerPoint 会自动缩字，字号会小于设计值） |

**处置原则**：ERROR 必须清零，不存在"先交再说"。WARN 逐条判断，依据是
"这一页教学上成立吗"，不是"工具报了就改"。阈值可用 `--thresholds` 覆盖
（脚本里的 `THRESHOLDS` 字典），但**改动阈值要写进交付说明**。

> 阈值的**教学依据**（每页几条要点、单条几个字、标题几个字）写在
> `teaching-slide-designer`；本表是它的机械实现。

### 第 5 步：PowerPoint 实开验收（不可省）

🔴 **结构自检全绿 ≠ 能打开 ≠ 放映正常。**
自检查的是关系图与 schema 约束，查不到"PowerPoint 喜不喜欢这个包"。
实测教训：一份结构自检全绿的 deck，PowerPoint 打开直接 `E_FAIL`（见「易错点」）。

所以验收必须做三件事：

1. **真开一次**：用 PowerPoint 打开（COM 自动化或人工），确认无「需要修复」提示；
2. **逐页导出 PNG**：把每页导成图，一页一张；
3. **拼版看一遍**：32 页缩成一张拼版图，**逐页**核对版面。

拼版图能一眼看出的问题：标题压线、卡片高度异常、强调色错位、角标露到块外、
某页只有一句话孤零零飘在中间。**只看单页容易漏，逐页扫拼版才抓得住。**

### 第 6 步：交付

必须同时交 **PPTX 本体**与**可编辑源（spec JSON）**：平台上传、后续重生成、
换图都靠后者。存档时把生成命令与阈值设置一起记下。

## 几何与视觉规范（单一事实源）

🔴 七种版式的几何**不是**散在渲染代码里的坐标，而是
`scripts/slide_layouts.py` 里的**版式原型表**。渲染器与判据**共用这一份** ——
两份几何各算一套，判据就会与画出来的东西漂移，那种判据没有价值。

### 画布与内容区

| 项 | 值 |
|---|---|
| 画布 | 720 × 405 pt（10 × 5.625 in，16:9） |
| 左边距 / 右边距 | 43.2 pt（0.6 in） |
| 内容宽 | 633.6 pt |
| 正文区上边 / 下边 | 120 pt / 36 pt ⇒ 正文可用高 257 pt |
| 两栏栏宽 / 栏距 | 309.6 pt / 14.4 pt |
| 图片宽 | 547.2 pt |
| 卡片内边距 | 14.4 pt |

### 字号（磅）

| 用途 | 字号 | 用途 | 字号 |
|---|---|---|---|
| 正文页标题 / 封面标题 | 23 | 卡片标题 | 14 |
| 正文 | 12 | 提示条 | 13 |
| 眉题 / 副标题 | 12 | 次级正文 | 11 |
| 引文 | 20 | 角标数字 | 10 |
| 页脚 | 10 | 图注 | 9 |

> **正文 12pt 是设计值，不是"越小越省地方"**：投影场景下还要按
> 实际教室的**最远可视距离**复核，宁可减条数也不要缩字号。

### 色板

| 令牌 | 值 | 用途 |
|---|---|---|
| `ink` | `1E293B` | 正文页标题 |
| `ink_deep` | `172554` | 封面 / 分节页标题 |
| `body` | `334155` | 正文 |
| `muted` | `64748B` | 眉题、页脚、图注 |
| `accent` | `2563EB` | 主强调色（蓝） |
| `card` | `F8FAFC` | 卡片底 |
| `rule` | `D1D5DB` | 分隔线 |
| `paper` | `FFFFFF` | 背景 / 两栏卡底 |

**多色强调体系**：8 套轮转，每套 = （强调色 / 极浅底 / 深色标题字）：
蓝 `2563EB`/`EFF6FF`/`1E3A8A`、青 `0891B2`/`ECFEFF`/`155E75`、
紫 `7C3AED`/`F5F3FF`/`6D28D9`、青绿 `0F766E`/`F0FDFA`/`115E59`、
绿 `16A34A`/`F0FDF4`/`15803D`、橙 `EA580C`/`FFF7ED`/`9A3412`、
粉 `DB2777`/`FCE7F3`/`BE185D`、琥珀 `D97706`/`FFFBEB`/`92400E`。

🔴 **强调色只由 `slides[].id` 决定**（`P1`… 按序号轮转），不依赖标题文字、
不依赖页序。这样**渲染器与判据看到的输入完全一样**，画出来的颜色与判据
以为的颜色不会分叉。

### 文字高度表（行高 = 字号 × 1.35）

| 字号 | 1 行 | 2 行 | 3 行 | 4 行 | 5 行 |
|---|---|---|---|---|---|
| 9pt（图注） | 13 | 25 | 37 | 49 | 61 |
| 10pt（页脚/角标） | 14 | 27 | 41 | 54 | 68 |
| 11pt（次级正文） | 15 | 30 | 45 | 60 | 75 |
| 12pt（正文/眉题） | 17 | 33 | 49 | 65 | 81 |
| 13pt（提示条） | 18 | 36 | 53 | 71 | 88 |
| 14pt（卡片标题） | 19 | 38 | 57 | 76 | 95 |
| 20pt（引文） | 27 | 54 | 81 | 108 | 135 |
| 23pt（页标题） | 32 | 63 | 94 | 125 | 156 |

> 表里每一格 = `ceil(字号 × 1.35 × 行数)`。自检会**逐格核对**这个公式，
> 不是只查"行数越多越高"—— 某一档凭感觉多写 1–5 pt 是手写这种表最常见的错，
> 那样会让溢出判据偏松、该报的报不出来。

**溢出怎么判**：一行能放多少字按 **em** 算（全角 1.0、半角 0.5），
`行宽容量 = (框宽 − 缩进) ÷ 字号`；段落行数 = ⌈文本宽度 ÷ 容量⌉；
所需高度 = 查表 + 段前距。**所需高度 > 框高 ⇒ 装不下**（判据 L15）。

🔴 **装不下 ≠ 看得见**：PowerPoint 的文本框带 `normAutofit`，
文字超出框高时**不会露出来**，而是**自动缩小字号** ——
于是"设计的 12pt"实际变成 9pt，而版面看起来还是正常的。这是**静默失效**。

### 卡片高度自适应

卡片（浅底 + 左侧强调条）的高度**随内容自适应**（3 条要点不该在下面留 200pt 空白），
但**上限是正文区高 257 pt** ⇒ 超出的部分由 L15 报出来，而不是让 PowerPoint 悄悄缩字。

## 中国高校语境要点

- **学时与页数配比**：经验值是每 45 分钟授课约 10–15 页（含封面与分节页），
  "新内容页"不超过一半，其余留给提问、演示与练习。以各校校历与班型为准。
- **大班 vs 小班**：合班百人以上的大班，每 45 分钟新内容页控制在 6–8 页。
- **投影 vs 智慧黑板**：智慧黑板可延展，关键步骤应**留白**而非预先写满；
  投影条件下正文少字、字号偏大。
- **机房与实验课**：页面以"操作步骤 + 预期现象 + 出错排查"三段为主。
- **课件要发到学习平台**：交付物**必须**含可编辑源（spec JSON）与可编辑文本，
  不要只交 PDF；上传版本要保留页内标题结构，便于课后检索。
- **讲稿与课程思政**：讲稿是课程思政案例的天然落点——案例写在讲稿里、
  正文只留结论句，既不挤占版面，又能在提问环节自然引出。

## 易错点

🔴 **三个 OOXML 契约坑（任何一个都会让 PowerPoint 直接拒开）**

1. **字号单位**：`sz` 的单位是**百分之一磅**（`ST_TextFontSize` schema 下限 100），
   不是磅。写 `sz="44"` ＝ 0.44 磅，违反 schema 下限 ⇒ **PowerPoint 硬拒（E_FAIL）**。
   正确写法：`sz="1200"` 表示 12pt。生成器内部一律用磅，写 XML 时 ×100。
2. **主题的 content type**：必须是
   `application/vnd.openxmlformats-officedocument.theme+xml` ——
   **没有 `.drawingml` 这一段**。写成 `...officedocument.drawingml.theme+xml`
   ⇒ PowerPoint 按 content type 装载主题时认不出来 ⇒ 母版主题断链 ⇒ **拒开**。
   🔴 且这类错**只换主题部件的内容修不好**，必须连 `[Content_Types].xml`
   里的声明一起对——所以判据必须落在**声明**上。
3. **段前距 `spcBef` 的位置**：它是 `<a:pPr>` 的**子元素**，且按 schema 顺序
   必须排在 `buClr` / `buFont` / `buChar` **之前**。当成 `<a:rPr>` 的属性拼进去
   ⇒ 位置既不合法也不合法为子元素 ⇒ schema 违规。

🔴 **两个不致命但会静默的坑**

4. **核心属性关系类型**：core-properties 的关系类型必须用 **package 命名空间**
   （`http://schemas.openxmlformats.org/package/2006/relationships`），
   不是 officeDocument 命名空间。PowerPoint 恰好容忍，但不该依赖它的宽容。
5. **扩展属性元素顺序**：`docProps/app.xml` 的元素顺序受 `CT_Properties` 序列约束，
   顺序错了严格校验器判非法。

🔴 **两个方法论坑**

6. **结构自检全绿 ≠ 能打开**：见上。**必须 PowerPoint 实开**。
7. **能打开 ≠ 放映正常**：文字装不下时 PowerPoint 会自动缩字号。
   必须**逐页导出 PNG + 拼版逐页核对**。

- ❌ 把生成器当成"能导出就行" → ✅ 生成器 + 结构自检 + 实开验收是三件独立的事。
- ❌ 把几何写进渲染函数 → ✅ 几何是数据（版式原型表），改坐标改一行表。
- ❌ 判据另写一套度量 → ✅ 判据与渲染器**共用同一个** `_paras_need()`。
- ❌ 只交 PPTX → ✅ 同时交 spec JSON；重生成、换图、平台上传都靠它。
- ❌ 封面做成多页 → ✅ `title` 版式全文只出现一次且在第 1 页。
- ❌ 把 `image-focus` 的图当装饰 → ✅ 图是这一页唯一的信息主体。
- ❌ 相信"导出成功" → ✅ 导出成功只说明写得出 PNG，不说明排版对。

## 方法论依据

- **PowerPoint 的 `normAutofit` 静默缩字**：文本框装不下时 PowerPoint 不报错，
  而是自动缩小字号并保持版面"正常"。这是**静默失效**，只能用几何判据
  （字号 × 框宽 ÷ em 容量）提前算出来，不能靠人眼看。
- **OOXML 是契约不是格式**：`sz` 的单位、content type 的拼写、元素顺序
  都受 schema 约束，违反即非法。这类约束必须用"机械推导 + 变异测试"守，
  不能只靠关系闭合检查——关系闭合全绿的包照样能被 PowerPoint 拒开。
- **单一真相原则**：版式几何只有一份（版式原型表），渲染器按它画、
  判据按它量；判据与渲染器共用同一个度量函数。两份几何各算一套，
  判据就会与画出来的东西漂移，那种判据没有价值。
- **可证伪的验收**：「结构自检全绿」不是验收，「PowerPoint 真能打开并逐页导出
  拼版核对」才是。前者只证明包自洽，后者才证明文件能用。
- **认知负荷与视觉层级**：一页同时呈现的要素越多，外在负荷越高。
  卡片高度随内容自适应、强调色轮转、两栏对照，都是为了让人一眼分清主次，
  而不是靠加粗和字号堆出"层次感"。
