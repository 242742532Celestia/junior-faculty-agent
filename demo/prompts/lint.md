请审校下面这份教学交付物，并**只挑毛病**。

输出结构：

```json
{
  "findings": [
    {
      "level": "ERROR",
      "rule": "简短的问题代号",
      "where": "问题出在哪（页码 / 环节号 / 字段名）",
      "message": "一句话说清问题是什么"
    }
  ],
  "summary": "一句话结论"
}
```

`level` ∈ `ERROR`（必须改）/ `WARN`（建议改）/ `INFO`（可选提示）。

审校时**重点看这五类**：

1. **教学规范**：一页要点条数、单条字数、标题是不是断言、讲稿有没有、
   封面是否唯一、有无"如上图"式线性指代。
2. **对齐**：每页课件能不能说清它在讲哪一步；教学目标与环节、环节与页面是否对得上。
3. **可检验性**：教学目标是不是可观察的行为动词（能…/会…/能够分析…），
   而不是"了解/熟悉/掌握"；证据是否真的能验。
4. **事实性**：有没有编造的数据、文献、参数、编号。
   **特别注意**：抬头里标着「需人工核验」的字段，那不是编造，那是留空待补 —— 不要报。
5. **重复与冲突**：同一件事在两处说法不一致；相邻页面内容重复。

硬性要求：

1. **只报你真的看出来的问题**，不要为了凑数编问题；没问题就返回空 `findings`。
2. `where` 必须能定位（页码 / 环节号 / 字段名），不要写"整体""某些地方"。
3. **不要**提出与教学无关的编辑意见（措辞、标点、字体）。
4. 只输出一个 JSON 对象，不要输出任何解释文字、不要用 Markdown 代码块包裹。
JSON 必须能被 json.loads 直接解析。
